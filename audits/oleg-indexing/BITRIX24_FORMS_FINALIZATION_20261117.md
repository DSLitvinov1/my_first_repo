## Решение по удалению и отключению

**Не удалять никаких CRM-форм сейчас.** По официальной справке Битрикс24 `https://helpdesk.bitrix24.ru/open/25221720/` удалённая форма не восстанавливается. Две рабочие формы оставить; их публичные ссылки уже используются в коде и связаны с прежними обращениями. Исторические скриншоты не доказывают отсутствие третьих и иных форм сегодня.

После входа владельца:
1. Выгрузить/сохранить текущий **полный** список форм, статусы, ID, URL, число отправок, связанные сайты и виджеты.
2. Для каждой неподтверждённой формы проверить использующие её виджеты, страницы, почтовые рассылки, роботов и архивные отправки.
3. Ненужные, **подтверждённо неиспользуемые** формы сначала **выключить**, сохранив идентификаторы и возможность быстрого включения. Настройки активных форм не трогать без доказательств.
4. Не выполнять удаление, пока нет отдельной описи и однозначного подтверждения, что форму нельзя использовать и её URL никому не нужен.

| Контроль дублей | объединять контакт по достоверному идентификатору при необходимости, **не поглощать отличные заявки и разные направления** | настройки форм, контактов и история 10/12; idempotency проверять отдельно |
| Поля и согласие | имя, телефон, тема/сообщение, разрешённое соглашение по ПДн, защита от спама | реальное отображение/валидатор формы; согласованный юридический текст |

| Автозадачи | один робот на новую сделку «Связаться с клиентом», Олег ответственный, без дублей | одна задача на одну сделку |
| Уведомления | подтверждённое Bitrix notification и/или email Олегу при новой CRM-форме | журнал доставки/уведомление у получателя, не просто настройка робота |

## Следующий конкретный шаг

**Владелец должен завершить штатный вход в Bitrix24 в ранее открытой управляемой вкладке на `WIN-LIDC05TBOQD`.** После появления авторизованного кабинета продолжить через Desktop Commander **только с разрешённой сессией**: инвентаризация → сравнение 2 форм → проверка опций active deal/duplicate → робот уведомления → проверка задач и личных уведомлений Олега → одна контролируемая end-to-end отправка только если исторических №10/12 недостаточно и есть возможность независимо проверить readback. Публикация исправленного сайта — отдельный gate после подтверждённых Timeweb source SHA, backup, rollback и миграции общего release pointer.

**Статус текущего шага:** inventory 2 historical forms `CONFIRMED_HISTORICAL`; full current inventory `AUTH_REQUIRED`; CRM settings changes `NOT_EXECUTED`; forms deleted/disabled `0`; new submissions `0`; production writes `0`; CRM final acceptance `NOT_PASSED`.
