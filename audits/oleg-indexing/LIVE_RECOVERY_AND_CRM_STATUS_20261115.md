## 2. Неполадки реальной загрузки форм

- [Playwright rootcause #43745046126](https://github.com/DSLitvinov1/my_first_repo/actions/runs/43745046126), безопасная диагностика без нажатия Submit. В отдельных запусках GET JS-ресурса `/b39421304/landing/assets/assets_webpack_...js` на стороне Битрикс24 отвалился с `net::ERR_HTTP2_PING_FAILED`. Это препятствует отображению iframe даже при HTTP200 страницы формы. В других запусках обе формы загружались в 3–4 секунды. **Инцидент плавающий; тест CI завершился failure, потому что при проблемных запусках даже прямая форма не отображалась**.
- Диагностика не установила причинную связь именно с мобильным экраном. Нельзя считать сайты полностью лишенными проблем с заявками.
- Подготовлен fallback UX: видимая ссылка «Открыть форму заявки» + телефон/почта из уже опубликованных `tel:` и `mailto:` ссылок. На главной он показывается в помощнике, на внутренних страницах — в footer. Прямой линк может тоже страдать от проблем внешнего Битрикс CDN, но телефон/почта предоставляют второй канал.
- Вспомогательная ссылка не собирает личные данные и не заявляет об успешной CRM-записи; никакой автопереадресации.
- [Playwright preview #43746360004](https://github.com/DSLitvinov1/my_first_repo/actions/runs/43746360004) PASS, 68/68 checks на 2 доменах × 2 размерах экрана × главная/услуга. ИЗМЕНЕНИЯ ТОЛЬКО В ТЕСТОВОМ БРАУЗЕРЕ, не опубликованы.

Защита от drift, dry-run, backup, проверка и откат сохраняются. ## 3. CRM Битрикс24 — что доказано и не доказано

- Ссылка на правильную форму и её HTTP 200 не равны созданной сделке. Сквозная цепочка «сайт → форма → запись CRM → ответственный Олег → уведомление» НЕ ПОДТВЕРЖДЕНА.
- Исторические два тестовых идентификатора `TEST-SEO-CRM-43664345430-consumer` и `TEST-SEO-CRM-43664345430-family`: один клик отправки на сайт, отсутствие независимого прочтения результатов в CRM; не посылать их повторно.
- Playwright Windows owner extension в настоящее время связан с Chromium, но известный работающий клиент имеет режим `connected_readonly_bitrix`, не write. Подтверждено [Actions #43744804494](https://github.com/DSLitvinov1/lesson3.1/actions/runs/43744804494).
- Разрешённая однократная read-only попытка посмотреть CRM-формы через тот же локальный Playwright [#43745693273](https://github.com/DSLitvinov1/lesson3.1/actions/runs/43745693273) создала команду, но результат `UNKNOWN_NO_RETRY`, код `AbortError:This operation was aborted`. Это НЕ доказательство наличия/отсутствия форм в админке. Команда не повторялась во избежание дублей.
- Для окончательной приёмки нужен **реальный просмотр списков лидов И сделок** в Bitrix24, фильтр по обоим тестовым идентификаторам, документальное подтверждение источника/времени/ответственного/уведомлений. Разрешённый browser/Work control или API read-only — не выдавать нынешнюю Chat-read-only вкладку за write access.
- При подтвержденном отсутствии тестовых лидов: исследовать CRM routing и согласие, затем создать только явно одобренный единичный тест с read-back. Не включать рекламу до этого.
