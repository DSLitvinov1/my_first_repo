1. Только после **нового** согласия `oleg.analytics.choice.v2` Яндекс Метрика запрашивает настоящий `ClientID` через официальный `ym(counter, 'getClientID', cb)`. Старое согласие `v1` не переносится автоматически на новую цель связи заявки с визитом.
2. ID не логируется, не хранится в новом локальном хранилище, не передаётся без согласия; проверка цифрового формата, не принимается произвольный ID из строки URL.
3. Строгая маршрутизация:
   - `potrebpravo.ru` — счётчик **114249897** — только `crm_form_fhi3n`;
   - `semya-yurist.ru` — счётчик **114251443** — только `crm_form_ep5fd`.
   Параметр формы — `metrica_client_id`, добавляется в URL собственной CRM-формы непосредственно при переходе по ссылке или открытии iframe. Внешние URL и чужая форма не меняются.
4. Сохранены существующие формы, интерфейс помощника, UTM, YCLID, события намерения `oleg_crm_form_open` и отказ посетителя. Новый код включён **в кандидате** на 45 HTML-страницах двух сайтов, 4 существующих JS-файла изменены, добавлены 2 собственных JS-файла.
5. Текст нового согласия и страницы приватности расширены описанием передачи ClientID в CRM. До публикации требуется юридическая проверка корректности согласия.
6. Подготовлен `conversion_router.py`: отдельные CSV `ClientId,Target,DateTime` только для реальных подтверждённых этапов «Консультация проведена» и «Договор заключён» и записей, имеющих реальные согласие/источник/проверенный ClientID. Реализованы точное соответствие источник→форма→счётчик, 21-дневный срок, защита от дублирования и неожиданных полей (включая PII), ограничение объёма, приватные CSV 0600 и отказ от перезаписи. **Загрузки по сети код не делает.**
