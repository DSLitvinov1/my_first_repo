## Точная граница готовности
**Подготовлено и проверено офлайн. Не опубликовано.** Не доказано, что параметр `metrica_client_id` настроен как скрытое поле **сделки** в каждой CRM-форме и сохраняется после настоящей отправки. Не доказана загрузка офлайн-конверсий в Метрику. Не использовать массовый официальный коннектор Яндекса для двух независимых счётчиков с общей CRM без подтверждённой фильтрации и правового основания.

## Следующий безопасный шаг
1. В действующем портале Битрикс24 штатным интерфейсом, с правами администратора CRM-форм, открыть обе формы. В экспертном режиме выбрать «Значения скрытых полей», создать/привязать строковое поле **сделки** для `metrica_client_id` и использовать настройку «Параметр». Сверить имена поля и параметра в реальной сохранённой конфигурации.
2. Только после этого внедрять сайт-скоупленный скрипт через проверенный атомарный релиз (с резервной копией и откатом).
3. По одной контролируемой заявке на каждый сайт — только с разрешения на обработку и строго с readback сделки; сохранить ID, правильный источник, форму, consent, ClientID без раскрытия в логах/репозитории.
4. Отправлять подтверждённые конверсии только в правильные счётчики по официальной схеме `ClientId,Target,DateTime`, проверяя валидные цели и 21-дневное окно привязки. Директ не запускать.
