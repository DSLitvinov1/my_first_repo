# Олег Legal — V25: проверенная передача UTM из двух сайтов в CRM-формы
Дата: 18.11.2026. Рабочая ветка: `oleg-v25-utm-attribution-20261118`.
Ветка V25 продолжает проверенную V24, не меняет существующий PR №125 и не публикует сайты автоматически.

## Подтверждённая первопричина
На V22 в обеих действующих юридических страницах CRM-формы Битрикс24 открываются через статические абсолютные адреса `https://b24-s2dosa.bitrix24site.ru/crm_form_fhi3n/` и `.../crm_form_ep5fd/` без UTM из URL страницы. Действующий `oleg-analytics-v1.js` сохраняет UTM в URL визита Метрики, но это не является передачей их в Битрикс24. По документации Битрикс24 прямые ссылки на CRM-форму с UTM в query могут сохранять метки в сделках после отправки формы. Факт сохранения в конкретном Битрикс24 Олега ещё не принят.

## Исправлено в исходниках — не в production
- `oleg-metrika-goals-v1.js`: при клике по прямой CRM-ссылке строго своего сайта дополняет URL только допустимыми `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`. Параметры произвольного типа, email, телефон, токены и опасные/длинные значения не переносятся. Нет регистрации `oleg_lead_success` без серверного подтверждения, по-прежнему соблюдаются существующие условия согласия на отправку целей Метрики.
- `legal-assistant-v4-utm.js`: адрес формы в iframe и её резервная прямая ссылка также получают те же ограниченные UTM из текущего URL сайта. При отсутствии меток URL формы не меняется. Чужие формы не используются.
- Текущая версия передаёт метки только из адреса той страницы, на которой посетитель открывает форму, без cross-page session tracking. Это честное ограничение, а не обещание «полного пути клиента».
- В V25 offline snapshot сформирована сборка для обоих сайтов: 168 исходных файлов, 49 изменяемых (27 потребительский сайт, 22 семейный); HTML cache-bust для JS помощника встроен в 23 и 18 страниц соответственно. Основная структура, контент и CRM-формы сохранены.
