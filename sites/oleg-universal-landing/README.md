# Юридический лендинг Олега — V2, 20.11.2026

**Статус:** тестовая разработка. Текущие сайты потребителей и семейного права не менялись; этот лендинг не опубликован, реклама не запущена, реальная CRM-интеграция не подтверждена.

## Вид и содержание
Новый светлый дизайн: белый/тёплый фон, оранжевые акценты, строгая типографика без фотографий и шаблонных весов правосудия. Сайт принципиально отличается от тёмных существующих площадок. На странице только заголовок, 8 компактных категорий услуг, форма, телефон, подвал. Убраны блоки FAQ, обещаний, процесса, ненастоящих отзывов. Телефон взят с двух опубликованных сайтов Олега.

## CRM
PHP адаптер: CSRF + same-origin + honeypot + rate limit + проверка согласия + идемпотентность. В серверном API: поиск контакта по телефону, создание при необходимости, отдельная сделка с UTM, yclid и кодом универсального лендинга, CRM readback сделки, затем только подтверждение в форме. Ошибки не выдаются за успешную заявку. Секреты не в GitHub и не в браузере.

Для реальной работы на выделенном HTTPS домене нужно задать без публикации в репозитории: OLEG_LANDING_PUBLIC_ORIGIN, OLEG_BITRIX_WEBHOOK_URL (штатный https://b24-xlzm11.bitrix24.ru/rest/... с правами CRM), OLEG_BITRIX_CATEGORY_ID, OLEG_BITRIX_ASSIGNED_BY_ID, OLEG_LANDING_STATE_DIR вне public_html. Необязательно: OLEG_BITRIX_SOURCE_ID, но только после проверки справочника. Потребительскую и семейную формы не перенастраивать.

**Проверка запуска:** одна контролируемая заявка → readback ID сделки → CRM источник/UTM/yclid/ответственный → уведомление Олегу. Пока реальный тест не проведён.

## SEO / GEO
Meta title, description, 1 H1, компактные семантические блоки 8 услуг, адаптивность, быстрый статический фронтенд, без внешних шрифтов и изображений. В тесте обязательные noindex и robots Disallow. Генератор seo/build_release.py делает публичную версию с canonical, sitemap, robots, OpenGraph, отдельным счётчиком Метрики и JSON-LD LegalService **только** после указания реального домена, утверждённой политики обработки данных и доказанных реквизитов владельца: наименование, фактический адрес, ИНН. Отдельная проверка на соответствие оператора документу. Без этого публикация блокируется. SEO не гарантирует позиции.

## Директ
seo/direct-structure.csv содержит 7 тематических групп, поисковые фразы, заголовки/тексты в официальных лимитах Яндекса, ссылки с предвыбором темы и уникальными UTM. Семейное и потребительское право рекомендовано рекламировать на двух уже работающих профильных сайтах. Дополнительно: seo/DIRECT_LAUNCH_GATES.md — требования к модерации и запуску. Кампании и оплата НЕ запущены.

Для юридической рекламы нужны реальные реквизиты исполнителя на продвигаемом сайте; не подставлять вымышленные данные. Реальные расходы только по отдельному решению. Яндекс Метрика: landing_phone_click, landing_topic_selected, landing_crm_accepted. Цель CRM достижима только после подтверждения сделки, и только при согласии посетителя.

## Финальная техническая доработка 20.11.2026

Дизайн V2 закреплён, HTML/CSS не тронуты. Улучшены интеграция Битрикс24 и контроль рисков: сделка привязывается через CONTACT_IDS, проверка существующей сделки по паре ORIGINATOR_ID/ORIGIN_ID до попытки создать новую, результат проверяется чтением ID/контакта/категории/ответственного/внешнего идентификатора, квитанции защищены отпечатком исходной заявки. После сетевой неопределённости повторного создания нет; допускается только безопасная сверка ранее созданной записи. Каталог квитанций обязателен, вне public root; отсутствующая настройка останавливает процесс. Подтвержденные прежним проектом значения категории 2 и пользователя 1 записаны в seo/RELEASE_CHECKLIST.md, но при запуске перепроверяются.

В seo/advertiser-review.json и seo/privacy-operator-review.html подготовлены по опубликованным политикам действующих сайтов реквизиты ООО «Центр управления правовой защиты» и проект политики. Они помечены pending; SEO-сборщик требует явного подтверждения оператора и утверждённого документа. Изменение статуса без проверки запрещено.

Добавлены проверки запрета небезопасных запросов tests/test_request_guards.py и сценариев наличия/отсутствия сделки tests/test_backend.php. Никаких реальных POST в Битрикс в рамках этих проверок нет. Страница по-прежнему noindex, рекламные кампании OFF. Требуется отдельный новый домен и верификация рабочего подключения CRM/счётчика; порядок запуска — seo/RELEASE_CHECKLIST.md.
