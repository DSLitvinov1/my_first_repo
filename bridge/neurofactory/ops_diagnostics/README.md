# Нейрозавод — изолированная диагностика сбоев

Этот экспериментальный модуль предназначен **только для чтения** заранее сохранённых снимков состояния GitHub Actions. Он не обращается к API, не запрашивает секреты и не изменяет очередь, контрольные точки, результаты Qwen, ветки или работающий компьютер.

Статус: **кандидат отдельной области OPS**, не подключён к основной системе и ожидает разрешения координатора по Issue №3. Ни один отчёт не является разрешением на публикацию.

## Что диагностируется

- Ошибочные, ожидающие и относящиеся к старому коммиту GitHub Actions;
- Наличие или отсутствие двух настоящих модельных запусков в представленном снимке;
- Отказ или отсутствие независимой проверки;
- Несовпадение идентификаторов коммитов и заданий;
- Неполные контрольные точки и неизвестные результаты публикации;
- Отсутствие обязательной защиты ветки и подозрение на изменение чужих файлов.

Предупреждение: данные входного файла **не аутентифицированы**. Объявленная модель, положительный REVIEW, данные о длительном хранении или запись о коммите не доказывают, что событие действительно имело место. Для выпуска необходимо отдельно проверять GitHub, владельца REVIEW и координатора. Этот модуль никогда не возвращает разрешение на публикацию.

## Использование

Передайте локальный JSON-снимок в сценарий `diagnose.py`. Результат — одна запись JSON с признаками сбоев. Автоматически скачивать GitHub-данные и запускать Qwen инструмент не умеет: это сознательно изолированный, безопасный режим. Пример формата проверяется в тесте `example()`.

## Проверка

Запустить `python -m unittest discover -s bridge/neurofactory/ops_diagnostics -p 'test_*.py' -v` с PYTHONPATH, указывающим на каталог модуля. Linux и Windows GitHub-hosted исполнители проверяют только примеры во временной директории без сетевых вызовов и чужих процессов.

## Ограничения и интеграция

- Не публиковать, не объединять и не использовать отчёт для обхода REVIEW.
- Не повторять Q090 и не резервировать Q091/Q092.
- Не возобновлять ChatGPT-отправку или платные API.
- Область OPS пока не внесена в карту владельцев. Только после явного решения координатора можно обсуждать её дальнейший состав.
- Подключение к реальному read-only GitHub API или UI — отдельная задача с собственной проверкой доступа и свежих данных.
