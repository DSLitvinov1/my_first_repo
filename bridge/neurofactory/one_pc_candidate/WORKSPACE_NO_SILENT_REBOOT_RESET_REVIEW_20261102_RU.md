## Исправление
- При полностью новом пути к данным первый запуск по-прежнему создаёт каталог и SQLite ровно один раз, `O_EXCL` и закрывает дескриптор; приложение не требует дополнительного ручного действия на свежем компьютере.
- При **существующей** директории и отсутствующем, усечённом или повреждённом SQLite программа отказывает. Использование SQLite `mode=rw` в `connect` запрещает молчаливое создание базы при исчезновении файла даже ПОСЛЕ успешного запуска.
- Для уже действующей схемы v3 перед запуском сверяются критические таблицы (projects, tasks, history, model_checks, task_proposals) и `PRAGMA quick_check`: удалённая таблица не восстанавливается пустой. Для старых корректных v0–v2 сохранён управляемый путь миграции с сохранением проектов/задач/истории, но не создаются пустые основные таблицы вместо исчезнувших. Неизвестные новые версии блокируются.
- Не добавлено ни одной полномочной команды CORE/HOST, модели остаются ненадёжными предложениями.

## Ограничения
Потеря ВСЕГО каталога данных может выглядеть как настоящий первый запуск (без независимо закреплённого признака прежней установки). Для криптографического отсутствия rollback нужен отдельный OS-protected install marker / независимый highwater, а не только Python. Этот фикс уменьшает случайную потерю данных, но не означает hardware antirollback.
Остались отдельный внешний физически независимый свидетель с mTLS/highwater, защищённая работающая SCM, подписанный Authenticode установщик, пользовательская Windows cold-boot приёмка и независимый человек-ревизор. Все прежние PR остаются DRAFT и не объединены.
