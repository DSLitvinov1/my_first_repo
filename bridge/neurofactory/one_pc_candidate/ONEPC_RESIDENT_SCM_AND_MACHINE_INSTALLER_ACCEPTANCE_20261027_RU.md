**Предмет:** продолжение уже испытанных PR №58, №60–64 без переделки CORE, настоящей Qwen, ранее испытанного подписанного admission и HOST. Дополнительно проверены **две новые** границы: настройка автоматического запуска/аварийного восстановления Windows-службы и единая машинная установка только-читающего пакета с HOST-исходниками.

## 1. Дежурная служба: действительная Windows SCM, автозапуск и восстановление

Добавлен `windows_setup/configure_resident_scm_ci.ps1`, принимающий исключительно один операторский CI-признак, защищённый маркер установки, точный SHA исходника, безопасный режим `REVIEW_BLOCKED_NOT_PRODUCTION`, имя `NeurofactoryCoreHost`, LocalService, уникальный RESTRICTED service SID и только абсолютный ожидаемый путь исполняемого файла. Чужую/продуктивную службу он не изменяет.

После проверки конфигурирует в одноразовом Windows-окружении `delayed-auto` и политику SCM restart после аварии с задержками 6 и 15 секунд. Читает реальную запись в реестре `DelayedAutoStart`, `sc qsidtype`, `sc qfailure` и Windows SCM. Тест принудительно завершает только тестовый сервисный процесс, дожидается нового Windows PID с состоянием RUNNING, читает заблокированную квитанцию и подтверждает, что CORE/HOST-код не выполнялся.

**PASS:** [GitHub Actions №40532366118](https://github.com/DSLitvinov1/my_first_repo/actions/runs/40532366118), точно протестированный SHA `7ebdb8b0427049f9336bec7f9765560c54e8abae`, квитанции `NF_ACTUAL_WINDOWS_SERVICE_AUTOSTART_AND_RESTART_AFTER_PROCESS_FAILURE=PASS_CI_ONLY`, `NF_ACTUAL_RESIDENT_CORE_HOST_TASK_EXECUTION=BLOCKED`.

**Граница доказанного:** после аварийного завершения Windows SCM возобновляет ограниченную дежурную службу; реальный холодный перезапуск Windows **ещё не испытывался**. Дежурная служба по-прежнему не получает доверенных ключей, очереди или разрешённых HOST-эффектов и **не является постоянным производственным исполнителем заданий**. Сам факт установки `delayed-auto` этого не меняет.

## 3. Необратимые блокирующие требования до производственного RELEASE

1. Настоящий Authenticode CodeSigning сертификат издателя, защита приватного ключа, offline подпись точного финального EXE, строгая внешняя проверка Windows trust-chain/thumbprint + pin установщика.
2. Реально независимые owner/reviewer/host/witness учётные и криптографические полномочия с подтверждённой принадлежностью репозитория, отзывом/ротацией ключей, без CI/private секретов в GitHub или EXE.
3. Отдельный на практике от восстанавливаемого компьютера внешний монотонный witness/highwater; свежий подтверждённый signed ACK; UNKNOWN/NO REPLAY в ошибочных случаях, реальная защита после отката полного системного диска.
4. **Постоянный активный**, а не dormant, сервис CORE–HOST с верным приёмом подписанных задач, настоящим CAS/fence/lease и без права модели создавать собственные разрешения. На сегодня подтверждён только ранее проверенный одноразовый безопасный цикл [Qwen+CORE+restricted SCM №39762142770](https://github.com/DSLitvinov1/my_first_repo/actions/runs/39762142770).
5. Точно соответствующие final SHA исполняемых файлов, справка о составе, независимое **собственное подписанное** APPROVED / REJECTED решение третьего ревизора по [Issue №11](https://github.com/DSLitvinov1/my_first_repo/issues/11), аппаратная/Windows проверка ПК владельца, перезагрузка/восстановление/обновление/отказ при компрометации.
6. Пока все перечисленные условия не выполнены: **NO MAIN MERGE, NO PROD DEPLOY, NO AUTO TASK EXECUTION, NO SKILLS, NO MODEL SOURCE APPLICATION**.

## 4. Порядок независимой приёмки этой лабораторной стадии

Ревизор должен взять конкретный SHA PR, отдельно сверить hash EXE, file manifest и Windows программные/NTFS ACL; проверить исполнение PowerShell от другого Windows SID, невозможность SCM-привилегий без доверенных root, rollback при сбое, фактический restart новой Windows-службы только при CI маркере, отсутствие HOST-effect. Ни автор PR, ни подписи временных CI-ключей не считаются независимым ревизором.

**Точный статус 27.10.2026: лабораторная упаковка и Windows SCM recovery технически испытаны; настоящий полностью подписанный и независимо принятый производственный установщик/исполнитель НЕ готов.**
