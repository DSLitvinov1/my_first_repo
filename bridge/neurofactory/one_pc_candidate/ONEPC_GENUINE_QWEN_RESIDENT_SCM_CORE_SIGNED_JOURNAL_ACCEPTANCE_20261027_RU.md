## Отдельный модуль журнала и тесты

**PASS: [№40541953622](https://github.com/DSLitvinov1/my_first_repo/actions/runs/40541953622), source SHA `25d51c1f2715377b92a8abcd4c3b31e46585b991`.** Шесть новых только адресных unit-тестов доказывают:

- повторное открытие и durable запись;
- отказ при отсутствии CORE `HOST_CHECKPOINTED_TEST`;
- запрет второго применения того же task ID;
- отказ при неизвестных полях, в том числе произвольном модельном тексте;
- отказ при повреждённом предыдущем хэше, заголовке, записи или отсутствующей SQLite таблице;
- отдельное чтение не создаёт и не «чинит» повреждённое хранилище.

**Важно:** локальная hash-chain SQLite НЕ противостоит администратору, который может полностью откатить или переписать ВСЮ базу; это не внешний независимый witness. Отсутствие автоматического повтора на существующем диске проверено, защиты при полной замене диска ещё нет.

### ЧТО НЕ ДОКАЗАНО И НЕ РАЗРЕШЕНО

- Текущий proof — единая cloud Windows CI-интеграция, **НЕ** физический холодный перезапуск пользовательского ПК и **НЕ** подписанный производственный исполняющий сервис. Настоящие Qwen + restricted SCM вместе **проверены**, но не установлены как непрерывная производственная конфигурация в едином подписанном installer с доверенными ключами.
- Ключи owner/HOST создаются **только временно внутри CI**, нельзя выдавать их за реальные полномочия владельца/независимого ревизора. Подписанный реальным издателем установщик и самостоятельно одобренный ревизором финальный SHA отсутствуют.
- Отдельный реально контролируемый внешний монотонный witness не подключён: при восстановлении всей машины/SQLite из старой резервной копии независимый antirollback ещё не доказан.
- HOST совершил ровно одно **безвредное заранее выбранное** действие, модельный текст не превратился в команды редактирования/публикации. Любое расширение привилегий требует отдельной приёмки и явного допуска владельца.
- Автоматический запуск через SCM на boot заявлен в конфигурации, но **холодный ребут Windows в полном E2E сценарии не проверялся**. Реальный аварийный restart с новым PID проверен.

## Требуемая независимая приёмка

Иной, уполномоченный на review подписант обязан сверить exact commit SHA, весь код изменения, Windows SID и effective ACL, signer custody, anti-replay после отключения питания/полного системного отката, отсутствие ключа в worker/model UI, release manifest и защищённый upgrade/rollback. Только после этих проверок можно рассматривать независимый APPROVED; до того `REVIEW_BLOCKED_NOT_PRODUCTION`.

**Итог:** цель сквозного лабораторного пути **Qwen → CORE → резидентный restricted SCM HOST → signed readback → local hash-chain journal → unattended crash recovery** достигнута на ОДНОЙ Windows-машине, но производственная установка и независимая приёмка не завершены. NO MAIN MERGE / NO OWNER PC / NO LIVE QUEUES / NO SKILLS.
