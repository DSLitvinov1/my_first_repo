## Что инженерно реализовано

Добавлен `scm_one_effect_witness_fence.py` поверх существующих CORE, recipient CORE guard, четырехстороннего signed bridge и TLS witness. Получатель требует совпадения exact full CORE spec SHA256, payload SHA256, task/project/source/lease/пинованного исполнителя с Ed25519 подписанными OWNER/REVIEWER claims. Перед **первым** сетевым обращением к remote witness (даже если позже будет потерян ответ) локальная получательская база SQLite в заранее подготовленном operator-only каталоге делает `BEGIN IMMEDIATE`, FULL sync и необратимую `UNKNOWN_NO_AUTO_RETRY` запись с UNIQUE task, operation, nonce и external epoch. Отдельная запись в существующем HOST attempt ledger также FULL-синхронизируется до TLS. После подписанного Ed25519 ACK от свидетеля CORE повторно наблюдается, а попытка остаётся израсходованной даже при аварии. Runtime никогда не пересоздаёт утраченный локальный журнал.

Добавлена **непроизводственная**, реально выполняемая только на disposable GitHub hosted Windows/Linux схема: один фиксированный безвредный файл внутри RUNNER_TEMP создаётся через CREATE_NEW только после проверки signed witness/CORE. Запрет на повтор проверен при невыданном ACK, испорченной подписи, иной задаче, просроченной аренде, потерянной базе, повторе из нового экземпляра, сбое сразу после ACK и до файла. На ПК пользователя эта функция прямо блокируется. Продуктовый HOST всё ещё не подключён к настоящему внешнему оператору и не производит реальные эффекты.

## Невозможность считать три ресурса одной ACID транзакцией

SQLite CORE, локальный HOST/recipient fence, отдельный highwater SQLite на другом узле и NTFS не имеют общей атомарной фиксации. Реализована безопасная **at-most-once / fail-closed saga**: расходуем запись до сети, допустим потерю эффекта и ручное расследование, никогда не повторяем автоматически, удостоверяем подписанный ACK и ещё раз проверяем CORE до инертного файла. Такое решение **не может честно гарантировать exactly-once** при привилегированном восстановлении нескольких прежних валидных снимков или при враждебной замене исполняемого кода. Не выдавать тестовый результат за подтверждение аппаратной защиты от отката.
