На одноразовой Windows-2025 GitHub-hosted машине добавлены и реально протестированы:

2. Защищённый NTFS каталог контроллера принадлежит строго Windows **SID отдельной учётной записи подписанта**. DACL допускает лишь тот же SID (учтены реальные Windows два owner-only ACE на каталог, в том числе ACE наследования файлов), любое чужое разрешение отклоняется.
3. Временная **вторая настоящая Windows-учётная запись** создаётся только в ephemeral CI; её SID проверяется через Windows API. Реальная попытка чтения ключа и публичного манифеста под этим SID отклонена ядром NTFS. Ложный несуществующий SID или SID самого подписанта также запрещены.
4. Отдельная офлайн-консоль `windows_owner_offline_cli.py` требует интерактивного терминала и ручного ввода индивидуального подтверждения. Она не открывает HTTP API, не устанавливает Windows-службы и не вызывает CORE. Headless запуск отклоняется.
5. Подпись связана с конкретным черновиком, проектом, моделью, исходным Git-коммитом/SHA-256, разрешённой целью записи, одноразовым nonce, двумя минутами действия и отдельным доменом Ed25519 для **учебного допуска только в очередь**, не для выполнения действий.
6. Публичный ключ должен быть **отдельно передан и закреплён у доверенного проверяющего**. В тестах он получен в памяти из временного контроллера. Локальный манифест сам по себе не создаёт независимый корень доверия.

## Что НЕ подтверждено и почему производство заблокировано

**Этот кандидат не установлен на компьютере владельца.** Временная CI подпись не доказывает физическое присутствие владельца, согласие на живые операции, доверенную конфигурацию его Windows и независимое право на окончательный запуск.

**DPAPI — защита от других Windows-учётных записей на диске, не неэкспортируемый аппаратный ключ.** Код, выполняющийся под SID подписанта, потенциально может вызывать DPAPI. Администраторы ОС/компрометация подписанта не исключены. Для релиза необходимо реально разделить самостоятельного UI-worker и оператора, запретить модели доступ к исполняемому коду подписанта, закрепить проверенный публичный ключ независимо от UI и защитить IPC.

**Консоль подписывает отдельный офлайн-файл.** Она не подключена как постоянно работающая служба TRUSTED HOST, не предоставляет браузеру или модели полномочия и не включает очередь автоматически. Подписанный файл должен затем пройти отдельную штатную проверку CORE на точную актуальную рабочую базу.

**Несвязанные БД и физический rollback.** Локальная workspace SQLite, CORE SQLite, NTFS и DPAPI не обеспечивают атомарность между собой и не свидетельствуют о невозможности полного отката диска. Не запускать опасные задачи автоматически при неизвестном завершении. Внешний защищённый highwater-свидетель или ручная сверка обязательны там, где требуется защита от rollback.

**Нет независимого одобрения REVIEW №11**, нет живого GitHub App с отдельными правами для самостоятельного размещения PR, нет установленного production Windows HOST, нет безопасно активированных SKILLS из PR №558. Ссылка на успешный CI — доказательство адресного теста, но НЕ независимый вердикт.

## Следующее необходимое изменение по критическому пути

Разработать и проверить **отдельную службу принятия подписанного офлайн-пакета**, с закреплённым независимо публичным ключом, чужим относительно модели Windows SID, защищённым локальным IPC, атомарной проверкой состояния CORE, строгим запретом повторной доставки, квитанцией и отказом при неизвестном исходе. Отдельно провести адресные отрицательные Windows-тесты IPC/ACL/rollback и пройти независимый REVIEW на точных SHA до любого реального развертывания на пользовательском ПК.
