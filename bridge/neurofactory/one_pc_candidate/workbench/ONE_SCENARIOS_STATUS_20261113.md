Дата: 13 ноября 2026. Продолжает существующий Work ONE 0.4 из commit `a46f791fb08b6737b12e2eba849360a3dec6e1fc` (PR #108). Новая ветка: `neurofactory-work-one-scenarios-20261113`. Защищённый CORE9/HOST, существующие Windows-службы, ключи, Qwen и рабочие клиентские программы не изменялись.

## Реализовано

- Выполнение нескольких последовательных браузерных действий по одному явно запущенному сценарию на русском языке.
- Допустимые шаги (от 1 до 12): «Открой https://...», «Нажми «Услуги»», «Напечатай в поле «Название» «Текст»», «Прокрути вниз/вверх», «Проверь текст «Готово»», «Сделай снимок».
- `browser_worker.cjs`: прямой поиск DOM-элемента по видимой подписи, защищённое реальное нажатие мышью, ввод текста через существующую клавиатуру Chromium, проверка текста на странице без возврата её полного содержимого. Это быстрее посекундного ручного наведения по изображениям.
- `workflow_one.py`: явное предварительное утверждение сценария пользователем, SHA-256 привязка точного исходного текста, отдельный запуск, одна конкурентная работа, последовательные контрольные точки SQLite, журнал действий, восстановление после остановки только как UNKNOWN_NO_RETRY, блокировка повторного запуска.
- В БД записываются идентификаторы и названия инструментов, но НЕ текст из поля или исходный сценарий. Снимок результата хранится только в памяти локального процесса, доступ к нему защищён локальным токеном владельца.
- Действующие проекты, редактор Work, Qwen для инертных черновиков, прежний веб-аудит и ручной браузер сохраняются.
- На локальном интерфейсе есть новая секция «Поручи агенту несколько действий»: текст задания, предпросмотр проверенных шагов, кнопка подтверждённого выполнения, статус шагов, снимок результата.
- У каждого инструмента есть проверка сайта, проекта, локальной сессии и допустимых параметров. Системная мышь Windows не затрагивается.

## Ограничения — строго не обещать как готовые функции

Это промежуточная архитектура универсального агента, **не функциональный эквивалент** всех возможностей ChatGPT Work, Desktop Commander, Google Agent и TinyFish.

- Нет произвольного понимания пользовательских задач Qwen как плана действий: принимает только ограниченные явные команды, модель не имеет права вызывать инструмент.
- Нет глобальной мыши и клавиатуры Windows, управления окнами, редакторами или файловой системой компьютера вне уже существующего Work sandbox.
- Нет активированных подключений Google, Gmail, Drive, Calendar, Bitrix24, TinyFish и прочих сторонних сервисов внутри самостоятельного приложения. Подключения ChatGPT автоматически в него не переносятся.
- Нет отправки форм, файлов, создания задач/сделок, смены настроек, удаления или публикации; сохранение в сторонних сервисах требует отдельной выдачи прав и проверки записи.
- Chromium пока не ограничен ОС-сетевой песочницей; использование пилота без проверки сетевых прав и изоляции в production не разрешено. Некоторые GET-действия на сайтах могут иметь побочные эффекты.
- Физическая установка в Windows, системная GUI-приёмка и подписанное разрешение CORE9/HOST на действия пока не проводились.

## Дальнейшая безопасная разработка

1. Отдельный Windows-only desktop controller: низкопривилегированный интерактивный пользователь, allowlist приложений/окон, машинная проверка владения процессом, безопасные координаты, запрет скрытого управления чужими приложениями, аварийное прекращение.
2. Подключаемые MCP/OAuth-инструменты с явно указанными правами и учётом расходов (Google, CRM, TinyFish, другие сервисы).
3. Qwen-планировщик выдаёт только структурированное предложение, обязательная серверная валидация, владелец утверждает план, CORE9 выдаёт ограниченное разрешение на каждый инструмент после отдельной защищённой приёмки.
4. Контроль результатов после записи в Bitrix24/Google, идемпотентность, скриншоты/журнал, откат, защита секретов и приватных данных.
5. Физические E2E-тесты Windows и независимая ревизия до публикации. Не сливать draft-ветки в действующие службы до этой стадии.
