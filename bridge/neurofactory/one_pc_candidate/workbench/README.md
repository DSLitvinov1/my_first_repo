# НЕЙРОЗАВОД WORK — локальная персональная мастерская (MVP 0.1)

Текущий объём: настоящие проекты, задачи, редактор исходных файлов, журнал изменений
и однократная генерация текстовых черновиков через существующую Qwen 3.5 9B на Linux.
Работает локально на одном Windows-компьютере. Без платных API и публичного доступа.

Это первый рабочий уровень аналога ChatGPT Work по пользовательскому сценарию.
Не эквивалент ChatGPT Work по полноте возможностей: пока нет автономного браузера,
универсального исполнения программ, агентского цикла разработки/исправления,
параллельных проектов CORE или сторонних интеграций.

## Состав

- work_server.py — локальный HTTP-сервер 127.0.0.1; без внешних зависимостей.
- work_core.py — SQLite и изолированные проектные файловые операции с историей.
- index.html, styles.css, app.js — адаптивный интерфейс без CDN, eval и внешних скриптов.
- test_workbench.py — адресные проверки реальных файлов, версий, защиты путей,
  SQLite после рестарта, одноразовой генерации, HTTP, CSRF и JSON.

Для черновиков Qwen переиспользуется реально установленный, проверенный
cloud_ssh_draft_provider.py с неизменной проверкой SHA256 по манифесту UI и
с отдельным жёстко зафиксированным хэшем. Приватный ключ не копируется и не
выводится из прежнего хранилища. Задание резервируется до SSH-вызова;
при неопределённом результате автоматический повтор запрещён.

## Локальный запуск

Проекты: C:\NeurofactoryProjects\projects\{project_id}
SQLite и журналы: C:\NeurofactoryProjects\.work-data
Интерфейс: http://127.0.0.1:8770/

Существующий embedded Python запускает work_server.py как обычный процесс
Windows-пользователя с параметрами --root, --data и --port 8770.
Новая программа не запускается под SYSTEM или служебным аккаунтом,
не устанавливается вместо NeurofactoryPersonalHost и не обновляет CORE9.

## Границы безопасности

1. Только локальный интерфейс; Host, Origin, собственный токен на запись;
   строгая CSP и отсутствие CORS.
2. Файлы внутри нового собственного каталога. Никаких абсолютных путей,
   .., NTFS reparse/junction, секретных и исполняемых файлов.
3. Изменение файла — только по нажатию пользователя. Перед записью сверяется
   SHA256, старая версия сохраняется в SQLite. Есть ручной откат.
4. SQLite фиксирует PENDING-интент до записи. После неоднозначного сбоя
   остаётся UNKNOWN_NO_RETRY, не производится автоматическое повторение.
5. Генерация Qwen — непроверенный текст, не запущенный код. Никаких
   команд, публикаций, платёжных API, прав администратора или бесконтрольных
   операций над компьютером.
6. Интерфейс пока НЕ запускает CORE9 напрямую. Интеграция в защищённый HOST
   требует нового ограниченного протокола разрешений и отдельной проверки.
7. Никакие действующие CRM, сайты и секреты заказчиков в новую мастерскую
   не переносились.

## Следующий инженерный этап

HOST с отдельными правами на чтение, запись ограниченных патчей,
изолированные Git-worktree и фиксированный набор безопасных команд сборки.
Управление состояниями многошаговой очереди, автоматический запуск
безопасных операций внутри одного проекта, откат и независимый журнал.
Не менять уже работающие подписанные цепочки CORE9/Windows/Linux.

## Испытания

На реальном Windows embedded CPython: 6 адресных тестов прошли,
локальный GET HTTP 200, браузерный скриншот интерфейса проверен.
Реальный модуль Qwen 3.5 доступен. Действующая защищённая служба
CORE9/HOST не перезапускалась и не изменялась.
