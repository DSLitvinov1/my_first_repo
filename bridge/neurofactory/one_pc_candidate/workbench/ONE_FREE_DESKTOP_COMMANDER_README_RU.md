# ONE Agent + бесплатный Desktop Commander MCP: безопасный кандидат

Дата: 2026-11-15. Отдельный кандидат к существующему Work ONE. **Не установлен на Windows и не подключён к этому чату ChatGPT.** Не объединять PR #124 / #126 с рабочей версией без физической приёмки.

## Что проверено

- Из исходного `wonderwhy-er/DesktopCommanderMCP` (`README.md`, `SECURITY.md`, `package.json`): локальный Desktop Commander MCP — MIT, версия в репозитории 0.3.3, требует Node.js >= 22.12.0; MCP-режим отличается от облачного платного Remote MCP.
- Desktop Commander MCP сам по себе **не управляет браузером** и не является SEO-агентом. Для Яндекс Директа, Метрики, Вебмастера, Битрикс24 и GSC нужен отдельный Playwright MCP/официальные API и отдельные разрешения владельца.
- В базовой ветке `workone-playwright-desktop-mcp-20261115` уже есть Playwright Extension candidate + отдельный ONE Desktop MCP + генератор двух локальных серверов. Здесь добавлен третий, `one-files`.
- **9 офлайн Python unit tests пройдены в локальной тестовой среде**; реальный Windows MCP handshake, установка Node-пакета, браузерное сопряжение и реальные SEO/CRM/Direct операции **НЕ ПРОВЕРЕНЫ**.

## Как построено

Модельный клиент совместимый с локальным MCP →
- `one-browser`: существующий локальный Playwright MCP + разрешённые пользователем вкладки Chrome;
- `one-desktop`: существующий ONE Desktop MCP с подтверждением владельца;
- `one-files`: `one_files_dc_mcp.py` → Desktop Commander MCP 0.3.3, только выбранные файловые операции с копией проекта.

Файловый мост допускает только `list_directory`, `read_file`, `read_multiple_files`, `get_file_info`, а после отдельного локального флага допускает `write_file`, `edit_block`, `create_directory`. **Нет** `start_process`, shell, `set_config_value`, удалённого режима, управления процессами, произвольного исполнения команд, внешних URL, секретных файлов. Рабочий каталог строго `C:\ChatGPTProjects\ONE-...`. MCP-сервер запускается только в локальном STDIO; сетевой порт не открывает.

Сетевые кабинеты и сайт Олега **не входят** в этот файловый контур. Облачный `Desktop Commander Remote` не заменён и месячная квота удалённого коннектора не обойдена. Прямое управление из обычного ChatGPT требует **отдельного разрешённого канала**; через существующий GitHub relay пока доступны только ранее объявленные операции и только после физической установки/сопряжения. Не выдавать этот генератор конфигурации за уже подключённый инструмент ChatGPT.

**ВНИМАНИЕ:** собственная документация Desktop Commander предупреждает, что `allowedDirectories` и `blockedCommands` не являются системной песочницей. Этот файловый посредник сокращает поверхность MCP, но для недоверенных данных использовать изоляцию ОС (виртуальная машина или Docker с ограниченными томами). Даже включение `--allow-write` не даёт права автоматически публиковать на сайтах.

## Активация владельцем (не выполнена)

1. В отдельной **обычной, не административной** пользовательской Windows-сессии создать тестовую папку, например `C:\ChatGPTProjects\ONE-DC-Isolated`, без паролей, ключей, файлов Битрикс24 и рекламных кабинетов.
2. Убедиться в наличии Node.js >=22.12 и Python, сверить установочный пакет `@wonderwhy-er/desktop-commander@0.3.3` с официальным репозиторием. Не включать облачный `remote`.
3. В тестовой копии Work ONE разместить этот модуль рядом с `owner_dual_mcp_config.py`, `one_desktop_owner_mcp.py` и Playwright config; рабочий ONE, CORE/HOST и Chrome-профиль не менять.
4. Запустить `owner_free_dc_config.py` с абсолютными локальными путями `--python`, `--workbench`, `--playwright-config`, `--root`, `--data`, `--workspace` и импортировать JSON в **совместимый локальный MCP-клиент**. Начать только с чтения.
5. Выполнить физическую проверку: чтение тестового файла из отдельной папки, отказ чтения `.env`, файлов за пределами папки, запрет терминала, проверка отсутствия сетевых публикаций и запрет непрошеных Chrome вкладок.
6. Только после этих проверок **отдельно** подтвердить работу с копией SEO-файлов с возможностью записи, тест diff → backup → edit → read-back, затем Playwright tab permission и безопасный тестовый сценарий на непроизводственной площадке.
7. Для команд из ChatGPT использовать ранее подготовленный GitHub Issue bridge PR #124 **после** проверки приёмки Windows. В нём сейчас нет произвольного исполнения Desktop Commander MCP; потребуется отдельный узко ограниченный диспетчер, а не общий remote shell.

## Критерии SEO/Директ

- Исправления SEO: подтверждённый исходный файл, резервная копия, точное изменение, тест страницы и подтверждённое развертывание. Перепубликация не происходит через файловый MCP автоматически.
- Для Яндекс Директа: только подтверждённые авторизованные вкладки, существующие черновики не дублировать; **никаких запусков, пополнений и расходов**.
- Для Метрики: проверка real submit event с Битрикс24, не путать с click.
- Для Битрикс24: отдельные разрешённые тестовые лиды, сверка CRM и уведомлений Олегу.
- Для Яндекс Вебмастера: проверка фактической индексации, а не только очереди переобхода.
- Основное задание: [lesson3.1 issue #1817](https://github.com/DSLitvinov1/lesson3.1/issues/1817).
