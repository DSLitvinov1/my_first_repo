# Нейрозавод Work ONE — личная переносимая Windows-версия

Сборка предназначена только владельцу. Она не устанавливает службы и не меняет действующие версии Нейрозавода, CORE9/HOST, CRM и прочие клиентские системы.

## Быстрый запуск

1. Распаковать скачанный архив целиком в отдельную папку на **личном Windows 10/11 x64**. Не извлекать отдельные файлы по одному.
2. Запустить **START_PRIVATE_WORK_ONE.ps1** в обычной интерактивной Windows-сессии, **не от имени администратора**.
3. Программа проверит подписи SHA256 по локальному манифесту и автоматически откроет браузер на `http://127.0.0.1:18770/`. Если браузер не открылся, можно вручную перейти по этому адресу. Оставлять окно запуска открытым во время работы.

Python 3.12, Node 24 и Puppeteer включены в архив. Установка Python/Node через интернет не требуется. На компьютере нужен установленный Microsoft Edge или Google Chrome (автоматический поиск в стандартных папках).

Рабочие проекты и база размещаются отдельно в `%LOCALAPPDATA%\NeirozavodWorkONEPrivatePilot`. Действующие программы на других портах остаются нетронутыми.

## Что уже можно делать

- Создавать изолированные проекты и задачи, работать с текстовыми файлами, просматривать историю и откатывать версии
- Управлять браузером на разрешённых HTTPS-хостах; по умолчанию example.org и Wikipedia (другие сайты подключаются пользователем через `-AllowedHosts`)
- Формировать сценарии по Qwen при наличии разрешённой локальной модели или существующего закреплённого Qwen-провайдера
- Запускать согласованные сценарии браузера и отдельно подтверждать создание/изменение задачи Google Tasks/Bitrix24 после независимой авторизации владельца
- Управлять окнами Windows, **только если пользователь при запуске явно указал допустимые приложения**; по умолчанию управление отключено

## Управление Windows

Проба на синтетическом файле: запуск `START_PRIVATE_WORK_ONE.ps1 -NotepadTest`. Программа откроет тестовый Блокнот в отдельной папке и включит доступ исключительно к `notepad.exe`; в интерфейсе надо прикрепить конкретный процесс. Клики/ввод требуют выбора окна и действий владельца.

Расширенные приложения могут быть разрешены только самим пользователем параметром `-AllowApps`, например для отдельных инструментов разработки. Work ONE не получает общесистемных полномочий, не выполняет shell-команды по ответу модели и не обходит UAC.

## Qwen 3.5

Бесплатная Ollama работает локально по `127.0.0.1:11434`. Поддерживаются установленная Qwen3.5 9B/4B/2B/0.8B, выбирается наиболее мощная из уже доступных. Если Ollama отсутствует, скрипт `SETUP_LOCAL_QWEN.ps1` покажет официальный сайт; он **не скачивает и не запускает неизвестный установщик**. После установки Ollama локальная Qwen может быть скачана по отдельному явно разрешённому запуску `SETUP_LOCAL_QWEN.ps1 -Pull` (по умолчанию 2B, потребуется несколько гигабайт свободного места). Если сохранён старый закреплённый SSH-провайдер Qwen, Work ONE попробует использовать его без копирования ключей.

Без модели функции Qwen будут обозначены как **не подключены**. Программа продолжит работать с локальными проектами и разрешённым браузером.

## Внешние сервисы

Google и Bitrix24 не авторизуются автоматически и не получают токены из ChatGPT. Подключаются отдельным явным действием владельца. Автоматические внешние записи запрещены: готовится операция, запрашивается подтверждение, выполняется чтение результата; в неопределённом состоянии повтор не происходит.

## Проверки и ограничения

Пакет собран в GitHub-hosted Windows 2025 из официального закреплённого Python и Node.js, содержит локальный SHA256-манифест. Проверены модульные и локальные HTTP-тесты, открытие интерфейса из встроенного Python, импорты Puppeteer из вложенного Node.

**Важно:** GitHub CI проверяет пакет на отдельной машине. Это **не** проверка установки на твоём конкретном ПК, не приёмка физической мыши/клавиатуры, не проверка скорости локальной Qwen и не доказательство полной автономности. Work ONE пока выполняет ограниченные, подтверждаемые сценарии, а не произвольные задачи без участия владельца.

В рамках ограничений Desktop Commander и SSH witness никакая удалённая установка на Windows не выполнялась. Для финальной физической приёмки нужен штатный разрешённый доступ к сеансу пользователя или запуск владельцем.
