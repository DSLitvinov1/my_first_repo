## Решение

Программа предназначена только владельцу и его личным задачам. **Не нужны** коммерческий релиз, публичный хостинг, биллинг, продажа лицензий, многопользовательские организации, публичный магазин или коммерческая упаковка.

**Нужны даже в личном режиме**: защита токенов, контроль прав, резервные копии, согласование записей, подтверждение результатов, понятная остановка ошибочных сценариев.

## Реализовано в этой ветке

`personal_readiness_one.py`: чистая, неразрушающая диагностика готовности:
- Qwen действительно подключена к текущему запущенному экземпляру Work, а не просто установлена где-то на сервере;
- разрешённый браузер доступен;
- пользовательская Windows-сессия и приложения явно разрешены;
- Google Tasks подключён с соответствующим scope;
- Bitrix24 подключён через разрешённый адаптер;
- отсутствие прав не выдаётся за успешную проверку;
- даже при наличии подключения реальная запись обозначена как **требующая живого теста**, а не автоматически проверенная.

`/api/private/readiness`: локальный HTTP endpoint, доступный только с токеном владельца. В интерфейсе — кнопка «Проверить возможности», краткий статус и следующий шаг. Диагностика не отправляет запросы наружу, не проверяет пароли, не публикует адреса порталов, пути к файлам или токены. Добавлены тесты, в том числе отказ доступа к диагностике без owner-token.

## Что осталось именно для личного использования

1. Установить/подключить текущую сборку Work ONE на **выбранном собственном** Windows-компьютере в непривилегированной пользовательской сессии. Проверить рабочие папки, снимки, ввод русских символов, аварийное прекращение, повторный запуск.
2. Обеспечить безопасный канал от Windows к Qwen на личном Linux-сервере (например, авторизованный локальный SSH tunnel), без публичного доступа к 11435 и без передачи ключей модели на другие машины без защищённого хранилища.
3. Пройти отдельную OAuth-авторизацию одного тестового Google аккаунта либо тестового Bitrix24; провести **настоящую** пробную запись только после пользовательского подтверждения и прочитать результат.
4. Добавить межпрограммный планировщик: одна цель → чтение → формирование предложения → подтверждение конкретной записи → выполнение → проверка. Сейчас Qwen умеет только ограниченный набор браузерных шагов, а внешняя запись отдельным подтверждаемым действием.
5. Проверить устойчивость: отсутствие доступа к GUI, ошибки Qwen/сети, смена окна, разрыв SSH, истечение OAuth, повторная отправка, резервная копия. Не отключать проверки ради скорости.
6. Принять личную версию (не коммерческий релиз) по нескольким реальным, разрешённым сценариям и сохранить точный рабочий commit.
