# Нейрозавод Work ONE 0.6 — техническая точка продолжения

Дата: 13 ноября 2026. Исходная ветка Work ONE 0.5 `neurofactory-work-one-scenarios-20261113`, исходный commit `cde9ae2a6b3c3d8337f7270f16e9e0fc52e6cef5`. Новая ветка `neurofactory-work-one-toolmesh-20261113`. Все существующие CORE9/HOST, Windows-службы, клиентские сайты и CRM оставлены без изменений. Новая версия пока отдельный DRAFT, не установленный коммерческий продукт.

## Реализовано в этой ветке

1. `desktop_worker.ps1`: управление выбранными окнами в интерактивной пользовательской сессии Windows. Проверяет точный PID/handle/path.exe и границы, разрешает только выбранный процесс из allowlist. Команды: список окон, привязка, скриншот, движение мыши, клик, ввод Unicode в UIAutomation.Edit/Document (не password), отключение. У каждого действия локальный nonce/session в `desktop_one.py`, журнал без текста и изображения. Режим включается ТОЛЬКО явно `--desktop-enable --desktop-allow-apps notepad.exe`, не в CORE9/HOST. Списки приложений нельзя задавать из ответа модели.
2. `qwen_planner_one.py`: Qwen 3.5:9b — только неисполняемый JSON-план; строгая схема, независимая серверная валидация через имеющийся `workflow_one.py`, разрешённые HTTPS-домены, до 12 безопасных шагов, утверждение владельцем. Адаптер локального Ollama на `127.0.0.1:11434`, плюс интеграция с ранее доверенным pinned Qwen SSH draft provider если установлен. Ни один ответ модели не запускает инструмент напрямую.
3. `credentials_one.py`: пользовательский зашифрованный DPAPI vault для OAuth-токенов и разрешений. Секреты не передаются в GitHub/логи/SQLite, на Linux vault выключен.
4. `google_oauth_one.py`: подтверждаемый пользователем Desktop OAuth Google PKCE через случайный loopback порт и проверяемый state; отдельно права Google Tasks, Drive metadata read-only, Gmail read-only, Calendar read-only; refresh/revoke локальных токенов. Требуется собственный Google Cloud Desktop OAuth Client ID в окружении `NF_GOOGLE_DESKTOP_CLIENT_ID`. Подключения ChatGPT нельзя незаметно скопировать.
5. `service_one.py`: Google Tasks create/update + чтение Tasks, метаданных Drive, списка Gmail и событий Calendar; Bitrix24 tasks create/update/get и чтение deal/contact с ОТДЕЛЬНЫМ CRM scope. Безопасные HTTP запросы: конкретные HTTPS хосты, публичный DNS, закреплённое TCP/IP, проверка TLS origin, без редиректов. Двухэтапная запись: подготовка → изменение блокируется при смене данных → подтверждение → запись → чтение результата. При неопределённом исходе UNKNOWN_NO_RETRY. В журнале только идентификаторы/методы, не клиентские данные.
6. `work_server.py`: API/CLI для всех вышеперечисленных модулей; локальный owner-token + Origin/Host, разделение проектов, выключено по умолчанию.
7. `toolmesh.js`, `index.html`, `styles.css`: единая интерактивная панель Qwen-плана, выбора окон Windows, пользовательского ввода/клика, Google OAuth и Bitrix24, двухэтапных защищённых задач и чтения записей. Предыдущие модули Work ONE v0.1–0.5 сохранены.

## Что проверено

- Linux: 41/41 Python unit/integration/regression тестов PASS (включены все предыдущие 28).
- Реальное Windows устройство WIN-MGERC7V1CQR в обычной сессии пользователя: PowerShell syntax, список окон, определение PID/handle, прикрепление к временному Блокноту, реальный click и SendInput English/Unicode в выбранное окно: команды вернули PASS; тестовый Блокнот закрыт. Прямое считывание текста кириллицы в редакторе через UIAutomation не поддержалось в этом тесте: фактическое содержимое ещё требуется подтверждать физической GUI-приёмкой.
- Browser smoke Work на Linux: новая панель отобразилась без JS ошибок, отключённые Qwen/Google/Windows корректно обозначены, при отсутствии аккаунта запись отклонена `SERVICE_PROVIDER_NOT_CONNECTED`.
- Мокированный OAuth PKCE: настоящий локальный callback и сохранение/отзыв синтетического токена успешно.
- Мокированные Google Tasks + Bitrix24 API: create/update, чтение результата, защита от незаявленной правки/повтора, fail closed. Реальных задач не создавали.
- Отдельный HTTP-test через Work: Qwen план → чтение → подготовка Google задачи → подтверждение → VERIFIED → повтор запрещён, на синтетических провайдерах. Сохранение данных в реальном подключённом Google/Bitrix НЕ проверялось.
- Windows GitHub CI по точному опубликованному коммиту следует проверить отдельно. Windows GUI E2E установленного приложения не проведён.

## Недоступные/незавершённые возможности

Не считать полной заменой ChatGPT Work, Desktop Commander, Google Agent или TinyFish: нет высокоуровневого автономного управления всеми приложениями, полноценной защищённой CORE9/HOST связки, реальной независимой приёмки/подписи, интеллектуальной верификации Windows UI, облачного TinyFish внутри Work, универсальных MCP-коннекторов, оплаты API, автоматической поддержки сторонних изменений. Qwen не подключён в обнаруженной Linux-среде (локальный Ollama не запущен), pinned Qwen Windows installation отсутствует на проверенном устройстве. Google OAuth Client ID и реальные Bitrix OAuth токены не предоставлялись; поэтому интеграции реализованы, но не авторизованы. Часть браузерных операций GET может иметь побочный эффект — OS/network sandbox необходим до production.
