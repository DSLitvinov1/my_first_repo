# NEIROZAVOD ONE — инженерный статус, 13.11.2026

## Граница текущего результата

ONE v0.2 — расширение существующей Work 0.1, а не отдельный Work/CORE9.
Доработка ограничена путями bridge/neurofactory/one_pc_candidate/workbench/
и существующим workflow этого модуля. CORE9, HOST, подписанные Linux-квитанции,
Qwen-провайдер, ключи, службы и задачи не изменяются.

База: Work PR #105, commit b87630f1d804e6e7d9ddc257e9a9df9fcaf27731.
Ветка: neurofactory-work-one-agent-safe-20261113.
Не объединять с production или защищёнными компонентами без ревизии.

## Реализовано

- Модуль agent_one.py: задание на 1–4 публичные HTTPS-страницы,
  последовательное выполнение, SQLite-транзакции, контроль повторов,
  хранение отчётов по страницам, UNKNOWN_NO_RETRY при прерывании.
- Сетевая защита: только HTTPS 443, без URL-логинов, IP-адресов,
  редиректов и прокси; все DNS-ответы проверены как публичные,
  TCP подключается к выбранному проверенному IP без повторного DNS,
  origin проверяется TLS/SNI, ограничены размер и тип ответа.
- Анализ HTML без запуска скриптов: title, description, robots,
  X-Robots-Tag, canonical, H1, формы и поля, hidden, количество ссылок.
  Замечания об индексации, пустом description, числе H1, скрытых формах.
- Встроен в существующий локальный Work UI и защищённый API с прежней
  Host/Origin/owner-token проверкой; вывод через textContent без HTML.
- Сохранены действующие проектный файловый редактор, задачи и
  Qwen draft provider без изменения его кода.
- Существующий Windows CI workflow расширен тестами нового модуля.

## Ограничения

Это не полная реализация ChatGPT Work, Desktop Commander, Google Agent,
TinyFish. Нет автономного кликанья в браузере, авторизованных сервисов,
произвольных команд, отправки писем, модификаций CRM, широких прав
на запись, удалённого computer use, вызовов инструментов моделью,
независимой приёмки новой CORE9/HOST-интеграции. Агент здесь —
ограниченный долговечный исполнитель явно запущенного действия.

Секреты, ключи, cookie, браузерные сессии не копировались.
Ни одна боевая система не перезапускалась и не обновлялась.

## Следующая инженерная последовательность

1. Ревизия ветки, Windows CI, безопасное развертывание отдельного
   пилота без замены действующей службы.
2. Browser Playwright: изолированный профиль, чтение, снимки экрана,
   затем ограниченные клики и отдельное разрешение для форм.
3. Desktop исполнитель в отдельной OS-песочнице с границами папок,
   allowlist, аудитом, защитой race/replay, управлением процессами.
4. Google-сервисы через OAuth/MCP-коннекторы с минимальными
   разрешениями; учёт каждого доступа и отзыва токенов.
5. TinyFish через отдельную авторизацию, политику доменов и
   контроль расходов; не копировать существующие сессии.
6. Qwen: только структурированные предложения действий, без прямых
   полномочий; подтверждение и защищённая очередь CORE9/HOST.
7. E2E: найти дефект, патч, тест, разрешение, применение,
   повторный тест, журнал, откат.
8. Реальная Windows-приёмка и публикация только после ревизии.

Пример: аудит сайтов Олега работает. Исправление сайтов и тестирование
реальных заявок требуют отдельного подключения исходников и CRM.
