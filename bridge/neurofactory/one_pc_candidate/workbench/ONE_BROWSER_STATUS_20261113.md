## Реализовано в отдельном кандидате Work ONE 0.3

- Изолированный Chromium через puppeteer-core 25.16.0, браузерная сессия открывается
  только действием пользователя в собственном локальном интерфейсе Work.
- Адреса: только явно разрешённые при запуске доменные имена, HTTPS 443,
  проверка общедоступных IPv4 DNS-ответов, DNS-пиннинг Chrome.
- Браузер умеет открывать страницу, выдавать JPEG-снимок, перемещать указатель,
  нажимать допустимые ссылки/кнопки координатами, прокручивать, возвращаться,
  показывать список видимых элементов и закрывать сессию.
- Работает на одной странице/временном профиле, без сохранения cookies, без
  подключения существующих аккаунтов и без чтения чужих браузерных профилей.
- Не выполняет действия форм: методы POST/PUT и переходы на другие домены запрещены,
  кнопки submit и поля форм отклоняются. Попытки открыть тел/почту и внешние ссылки
  тоже отклоняются. Известный риск побочных эффектов через GET остаётся; для
  production обязательна ОС-песочница egress и отдельное право на критические действия.
- Контроль одной браузерной сессии, project/session binding, owner-origin token,
  лимиты координат, timeout/UNKNOWN_NO_RETRY и журнал действий без параметров URL.
- Браузерная мышь работает ВНУТРИ страницы на снимке Work, системная мышь
  Windows пока не управляется. Не выдавать её за физический desktop control.

## Как включать браузерный пилот локально

Зависимости: Node.js >=22, npm ci (пусть пакет остаётся только в каталоге
workbench), установленный совместимый Chromium/Chrome. По умолчанию модуль
ВЫКЛЮЧЕН и требует явного browser-executable и browser-allow-hosts с точными
проверенными доменами. Приложение слушает только 127.0.0.1, не выводить его
наружу и не запускать под администратором/SYSTEM.

На Linux тесте: exe=/home/cloudagent/.cache/ms-playwright/chromium_headless_shell-1248/chrome-headless-shell-linux64/chrome-headless-shell
и пользовательский LD_LIBRARY_PATH с существующими libnspr/NSS/ATK.
Для Windows нужен отдельный owner-процесс с собственным Node/Chrome и
полной физической приёмкой. Windows-сервис CORE9/HOST не менять.
