## БЕЗОПАСНОЕ ПРЕДОСТАВЛЕНИЕ РЕАЛЬНОГО ДОСТУПА ПОСЛЕ НАЗНАЧЕНИЯ

**GitHub**: отдельный именованный аккаунт ревизора, минимально необходимый read-only доступ к исходникам, diff, логам CI и build artifacts; доступ не делится с владельцем. Не выдавать токены или учётные данные в чат.

**Windows владельца**: сначала окончательно подготовить защищённую SCM-службу и согласовать отдельную локальную приёмку. Дать ревизору временную ограниченную read-only сессию/выгрузку статусов SCM, DACL/SID, Authenticode и слепок проверяемого журнала без токенов/приватных ключей. Не создавать ему Administrator/RDP root, не включать remote desktop публично. Ни этот документ, ни подключённый инструмент Remote Desktop Commander не равнозначны приглашению внешнего ревизора.

**Независимый Linux VPS witness**: требуется отдельный управляющий/хранитель ключей, которого владелец назначит явно. Доверенный оператор отдельно развёртывает сервис с root-owned config, закрытым VPN/mTLS и постоянным highwater. Ревизору можно предоставить отдельный краткосрочный read-only SSH аккаунт с ограниченной командой аудита или заверенную операторскую выгрузку показателей, но не root, не witness signing key и не приватную TLS key. Доступ ревизора к тому же пользовательскому Ubuntu-аккаунту `cloudagent` **не доказывает** независимое хранение/контроль.

**Защита данных**: никакие приватные ключи, DPAPI-секреты, сертификатные ключи, API токены, пароли и SSH credentials в PR, GitHub issue или чат. Снаружи не открывать новые порты и не менять firewall ради аудита. Выдача SSH/RDP-прав требует точного имени проверяемого адресата и согласованной минимальной роли.
