# НЕЙРОЗАВОД — отдельный Linux VPS свидетеля: инструкции оператору

Контрольная точка 27.10.2026. ДАННЫЙ ПАКЕТ НЕ ОЗНАЧАЕТ, ЧТО VPS УЖЕ КУПЛЕН, ИМЕЕТ ИЗДАТЕЛЬСКУЮ ПОДПИСЬ ИЛИ ОДОБРЕН НЕЗАВИСИМЫМ РЕВИЗОРОМ. Использовать для подготовки **нового пустого сервера**, отдельно от рабочих CRM, отелей, сайтов и Windows-машины владельца.

## Предварительно выбранная конфигурация, НЕ заказана

Timeweb Cloud, Cloud-40: 2 vCPU, 2 ГБ RAM, 40 ГБ NVMe, тариф на официальной странице `https://timeweb.cloud/services/cloud-servers` на 27.10.2026 около 900 ₽ в месяц при помесячной оплате (дополнительные опции/бэкапы/VPN оплачиваются отдельно по фактическому счёту). Ubuntu 24.04 LTS, x86_64. Хранение проверенных разрешений и монотонного состояния, не запуск Qwen. У оператора должны быть права владения **новой отдельной** машиной, без общего SSH-токена с Windows/CRM и без других сервисов в рабочем окружении.

**Не покупать автоматически**: в текущей сессии нет подключённого аккаунта Timeweb Cloud/VPS, и инструментов принятия платежа. Пользователь разрешил приобретение отдельного VPS, но создание экземпляра, реальный IP, ключи SSH, VPN, защищённое хранилище и фактическая оплата ещё не подтверждены.

## Сеть и реальные ключи

Служба принимает только числовой IPv4 на точном назначенном частном интерфейсе из сетей 10/8, 172.16/12 или 192.168/16. Должен быть отдельный приватный VPN/закрытый сетевой маршрут между Windows владельца и VPS (например, WireGuard с предварительно настроенными ключами и firewall). Публичный 0.0.0.0:порт запрещён; из интернета не открывать. DNS-имя сертификата свидетеля (`witness.<ваш приватный домен>`) и точный сертификат сервера должны заранее независимо закрепляться на Windows. Для VPS-файрвола разрешить порт лишь с адреса одного клиента по VPN, остальные запретить; исходящий доступ свидетелю, кроме необходимых обновлений по расписанию, ограничить.

**Отдельный независимый оператор** подготавливает и хранит вне GitHub:
- root-owned конфигурацию `/etc/neurofactory/witness/production.json` с точным source SHA40, SHA256 утверждённого установщика, машинным SHA256 Windows, Ed25519 SHA256 публичного ключа свидетеля, TLS DER SHA256 сервера, TLS DER SHA256 разрешённого Windows клиента, ID независимого свидетеля и единственным приватным IPv4/портом;
- root-owned TLS server certificate `/etc/neurofactory/witness/server.pem` и CA сертификат разрешённых клиентов `/etc/neurofactory/witness/clients-ca.pem`;
- сертификатный секрет сервера `/var/lib/neurofactory-witness/server.key` и отдельный 32-байтный Ed25519 private signer `/var/lib/neurofactory-witness/witness-private.key`, каждый 0600 owner dedicated Linux UID, никогда не выкладывать в артефакты/логи/чат/репозиторий;
- уже отдельно **оператором** инициализированный ledger `/var/lib/neurofactory-witness/remote-ledger.sqlite3` с 0600 и систематическими независимыми резервными копиями/механизмом WORM/неоткатываемым внешним floor. Только этот VPS без WORM не даёт защиты при полном откате самого VPS.

## Размещение кода и systemd

После независимой проверки точной версии GitHub-коммита, SHA файлов и состава архивного пакета доверенный администратор устанавливает исходники только в `/opt/neurofactory-witness/app/` (ownership root:root, нет записи сервисному UID), отдельное Python 3.12 окружение в `/opt/neurofactory-witness/.venv`, с криптографической библиотекой версии 46.0.3 и заранее закреплёнными по SHA256 официальными wheels. В GitHub сейчас нет подписанного производственного артефакта или опубликованной доверенной wheel lock-цепочки, поэтому автоматическая установка в production до REVIEW запрещена.

Создайте отдельного Linux пользователя `neurofactory-witness`, исключённого из sudo, docker и login. Для конфигурации создать root-owned каталог `/etc/neurofactory/witness` с доступом service-группе только на чтение; для `/var/lib/neurofactory-witness` — service-owned директорию 0700. Проверьте, что service UID не может изменять root-owned production.json, CA, бинарные библиотеки, systemd unit или исходники Python.

Шаблон systemd `vps_witness_systemd/neurofactory-witness.service` устанавливается в `/etc/systemd/system/neurofactory-witness.service` только после отдельного аудита. Его `ExecStartPre --audit` не выдаёт разрешения и запрещает запуск без provisioned root-owned pins, совпадения публичного Ed25519 с реально установленным приватным ключом, полного TLS DER thumbprint и непротиворечивой SQLite-БД. `ExecStart --serve` слушает частный IP, TLS1.3 с проверкой DER SHA256 клиента, фиксирует epoch + operation уникально, подписывает Ed25519 ACK **после commit**. `Restart=on-failure` даёт перезапуск процесса, но не повторяет неизвестную операцию.

Для независимого приёмочного теста оператор после реального сетевого и signer enrollment должен отдельно, с предварительной записью исходного highwater, проверить: (1) запуск systemd при загрузке VPS; (2) второй владелец Linux не читает signer key и не пишет базу; (3) некорректные cert/client/nonce/epoch/sha/пакет отклоняются; (4) kill -9 процесса восстанавливается без потери состояния; (5) отключение сети в момент подписанного ACK оставляет UNKNOWN без автоматического повтора; (6) восстановление старого снимка Windows не переоткрывает заблокированное на VPS задание; (7) восстановление снимка VPS обнаруживается при сравнении с независимо закреплённым floor/WORM, иначе производство **НЕ ОДОБРЯТЬ**.
