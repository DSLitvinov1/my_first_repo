НЕЙРОЗАВОД — локальный интеграционный кандидат, НЕ выпуск

В составе установщика теперь присутствуют неизменяемые исходные
компоненты CORE, TRUSTED HOST, PROVIDERS и COORDINATOR, взятые из
точных Git-коммитов. Проверьте components\\manifest.json: в нём
перечислены версии и SHA-256 каждой копии. Эти файлы ещё НЕ
связаны с действующей рабочей очередью и не являются установленной
Windows-службой. Сама копия исходника не означает наличие защищённого
исполнителя или самостоятельного запуска Qwen.

Работает прежняя локальная база SQLite, создание проектов и черновиков,
диагностика и резервное копирование. Проверка доступной Ollama/Qwen
выполняется только по нажатию пользователя. Никаких автоматических
загрузок моделей, регистрации службы, изменения прав и выполнения
заданий CORE этот установщик НЕ делает.

Данные находятся в %LOCALAPPDATA%\\NeurofactoryData.
Откройте программу с ярлыка или http://127.0.0.1:8766/.
При обновлении и удалении программы база пользователя сохраняется;
перед любым обновлением создайте резервную копию.

Следующие незавершённые обязательные этапы:
интегрировать защищённую ОС-службу с сервером и CORE с явным
разрешением владельца, провести настоящую Qwen и полный сквозной
тест на временной Windows-машине, а затем независимую REVIEW.
Производственный запуск, HANDOFF и публикация отключены.

Восстановление из резервной копии:
- Завершите работу локального приложения.
- Найдите резервный файл workspace-*.sqlite3 в каталоге
  %LOCALAPPDATA%\\NeurofactoryData\\backups.
- Восстановление выполняется приложенным инструментом
  app\\restore_offline.py только в НОВУЮ пустую папку данных.
- Инструмент проверяет целостность SQLite, наличие правильной схемы,
  состояние черновиков и запрещает перезапись существующей базы.
- После проверки восстановленного каталога можно отдельно выбрать
  его при следующем запуске. Автоматической замены активной базы нет.
- Перед обновлением и восстановлением сохраните независимую копию
  исходных пользовательских данных.

ДОПОЛНИТЕЛЬНО: ПРОСМОТР CORE ТОЛЬКО ДЛЯ НАБЛЮДЕНИЯ
По умолчанию интерфейс сообщает «CORE не подключён».
Уполномоченный оператор вправе при ручном запуске приложения указать
--core-state-dir и абсолютный путь к уже существующему PRIVATE-каталогу
с queue.sqlite3, если его Windows-учётная запись имеет право чтения.
Программа НЕ создаёт такую очередь, НЕ записывает в неё, НЕ запускает
модель, НЕ оформляет разрешения HOST и НЕ повторяет задания.
Доступны только идентификатор задания, проект, модель, состояние
и число попыток без подписи, ключей, токенов и полного содержимого.
Локальный статус HOST_CHECKPOINTED_TEST не является независимой
аттестацией или разрешением на производственный запуск. При ошибке
чтения отображается недоступное состояние; автоматического
исправления или повторного выполнения нет.

ПОДГОТОВКА ЗАДАНИЯ ДЛЯ ЗАЩИЩЁННОЙ ОЧЕРЕДИ CORE
На экране «Локальная база» рядом с черновиком появилась кнопка
«Подготовить запрос на допуск CORE». Она читает сохранённое задание,
проверяет существование проекта и строгую совместимость с контрактом
CORE (одна строка, от 25 до 320 символов, поддерживаемая модель).
Показывается идентификатор и SHA-256 подготовленного запроса.
Это только чтение: очередь и защищённая служба НЕ запускаются.

Отдельный модуль signed_owner_admission.py реализует проверку
подлинного Ed25519 разрешения из внешнего доверенного источника.
Разрешение подписывает точную связку: черновик, проект, назначенная
локальная модель, единичный целевой путь, исходный Git-коммит,
SHA-256 исходника, время действия и случайный идентификатор.
Только после проверки подписанного разрешения отдельный уполномоченный
HOST-контроллер может вызвать штатный OneTaskCore.enqueue.
В лабораторных Windows-испытаниях проверено реальное сохранение
задачи в CORE SQLite. Браузер этого действия делать не может.

ВАЖНО: в установленном пользовательском приложении пока НЕТ
доверенного контроллера с отдельно защищённым ключом владельца.
Ключи не лежат в браузере, базе черновиков и программе установки;
тестовый Ed25519 ключ создаётся только на изолированной Windows CI.
Установщик не получает права создавать очередь и не устанавливает HOST.
Текст «отправлено в CORE» показывать без отдельного подтверждения нельзя.
Существующие черновики не переводятся в «Выполнено» автоматически.
После возможного сбоя при допуске не повторять попытку: сначала
проверить сохранённое состояние CORE. Защита от полного отката диска
без независимого свидетеля не гарантирована.


ОПЦИОНАЛЬНЫЕ ИНСТРУМЕНТЫ CODEX И CHATGPT SITES
В панели есть раздел «Codex и Sites». Пользователь выбирает свой проект,
сохраняет в SQLite обычный черновик и копирует готовое задание для Codex
или ChatGPT Sites. Никакой текст не отправляется в OpenAI автоматически.
Два внешних продукта требуют отдельного входа в ChatGPT и действуют
в пределах лимитов учётной записи. Sites запускается через ChatGPT Work;
публикация и подключение домена требуют отдельного согласия.

В каталоге app/codex_sites_bridge.py находится необязательный
локальный адаптер Codex CLI для работы только в режиме чтения.
Он не запускается при старте программы и не доступен по HTTP. Для
ручного запуска понадобится отдельно установленная официальная
версия Codex CLI, вход пользователя, явно выбранная Git-папка,
разрешение владельца и действующие лимиты ChatGPT. Скрипт не хранит
ключи и не даёт CORE/HOST прав на исполнение. Владелец должен
разрешить передачу исходного текста внешнему сервису.

Это не интеграция с публичным Sites API. Веб-сайты
сохраняются и публикуются через официальный интерфейс ChatGPT.
