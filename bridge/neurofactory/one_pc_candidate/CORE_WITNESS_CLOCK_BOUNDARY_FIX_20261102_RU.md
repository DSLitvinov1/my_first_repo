# НЕЙРОЗАВОД — P0 исправление времени CORE→HOST перед резервированием свидетеля
Дата: 02.11.2026. Только DRAFT, **не промышленный выпуск**.

## Основание
Внутренний AI-аудит Issue #11 (комментарий https://github.com/DSLitvinov1/my_first_repo/issues/11#issuecomment-6584032804) обнаружил, что вызывающий код мог подставить старое `now_unix` при уже истёкшей CORE lease. До исправления локальный read-only preflight мог вернуть статус `LOCAL_CORE_SCOPE_MATCHED_AND_SIGNED_REMOTE_ACK_TEST_NO_EFFECT` с фиктивным временем, не предоставляя производственных эффектов.

## Изменение
Новая ветка `neurofactory-host-clock-preflight-20261102` основана строго на DRAFT PR #77 HEAD `0084c4176baf52a25e49a966d2913bc5f222aba7`.
В `protected_host_core_witness_binding.py`:
- до чтения CORE, резервирования локального журнала и любого сетевого вызова сверяется `now_unix` с фактическим временем ОС; допуск расхождения не более 5 секунд, иначе отказ;
- для проверки CORE lease и передачи в signed bridge используется фактически прочитанное время ОС, а не слепо принятый аргумент;
- после remote ACK часы проверяются повторно; изменение времени больше 5 секунд, обратный ход времени или истечение подписанного claim переводят результат в `UNKNOWN_NO_RETRY`, а не в положительный локальный preflight.
Никаких новых полномочий, ключей, установщиков, внешних сетевых портов и изменений CORE/Windows SCM не добавлено.

## Адресная проверка
Подключённая Linux лаборатория `litd12123.clodocd.com`, отдельный временный git worktree на точном кодовом SHA `692fbfcf8a6f01fa382319f2375701b9350da4e5`. `git diff --check` — PASS; `python3 -B -m unittest -q test_protected_host_core_witness_binding` — **30 tests OK за 1.751s**, в том числе два новых сценария: устаревшее вызывающее время отказывается ДО mock network; скачок времени ПОСЛЕ mock ACK даёт `CoreWitnessBindingUnknown` и не повторяет запрос. Временная SQLite и отдельные тестовые ключи; реальный VPS не вызывался, файлы проекта не исполнялись.

## Что НЕ доказано
ОС-часы локальной лаборатории не являются доверенным защищённым источником времени; локальный привилегированный оператор может менять системные часы. Остаётся блокер из Issue #11: `operation_sha256` подписанного claim не привязан к полному canonical CORE spec/target/payload. **Этим PR он не исправляется**. Физический Windows SCM Host на компьютере владельца не установлен; Linux `neurofactory-witness` не активен и не имеет production config/ledger; независимая физическая приёмка и Authenticode не подтверждены. Нужны доверенные внешние epoch/highwater и OS fencing, затем независимая приёмка конкретных SHA.

## Решение
`LOCAL_TARGETED_PASS / PRODUCTION_REJECT`. Сохранять DRAFT, не объединять, не запускать очереди/HANDOFF и не объявлять независимый APPROVE.
