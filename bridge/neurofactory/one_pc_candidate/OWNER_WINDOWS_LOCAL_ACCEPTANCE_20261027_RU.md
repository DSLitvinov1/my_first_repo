# НЕЙРОЗАВОД — локальная установка на компьютере владельца, контрольная точка 27.10.2026

## Что разрешено и что фактически проверено

Владелец просит довести локальную Windows-установку и приёмку программы до положительного результата без покупки VPS. **Это согласие на безопасное локальное испытание, но не на принудительную установку неподписанного привилегированного HOST или автоматическое скачивание моделей.**

Канал Remote Desktop Commander подключён, но 27.10.2026 запрос состояния аккаунта сообщил `remote_calls_left_pct: 0`; через него реального доступа к физическому компьютеру нет. API GitHub Actions `/actions/runners` для текущего GitHub инструмента недоступен; онлайн-состояние резервного GitHub Windows self-hosted Runner не подтверждено. Нельзя выдавать GitHub-hosted CI за установленное приложение на компьютере владельца.

### Подтверждённая локальная приёмка на disposable GitHub Windows

**PASS [Actions №40554294409](https://github.com/DSLitvinov1/my_first_repo/actions/runs/40554294409)**, точный SHA исполняемого исходника `9ef6ebf152d3fc5df99cd4132500fed7867499ad`. В этой же проверке впервые выполнен новый модуль `windows_setup/owner_pc_readonly_acceptance.ps1`.

Подтверждено:
1. Настоящий x64 Inno installer **per-user**, не требующий права администратора, подготавливается из заранее pin-доказанных 15 компонентов CORE/HOST/PROVIDERS/COORDINATOR, embedded Python 3.12.10 с официально закреплённым SHA и локального интерфейса.
2. Windows install в приватную директорию гостевого тестового пользователя GitHub Actions, запуск Python SQLite HTTP только на localhost, создание одного проекта и безопасного DRAFT задания. Создание/исполнение реальных CORE-HOST задач выключено.
3. Проверка исходников 15 компонент по хэшу, provider/CORE import без model inference, защита от изменённого файла; SQLite backup и restore into empty isolated folder; повторный запуск UI с сохранением проектов/черновиков.
4. **Новый собственный офлайн-аудит** сверяет полный SHA256 `components/manifest.json` с digest, полученным из **отдельной staging-директории до установки**, проверяет каждый из 15 файлов после установки, отсутствие допущенной HOST-службы, не выдаёт живой execution authority, отдельно по желанию может лишь прочитать локальный Ollama `/api/tags` на 127.0.0.1:11434 (не делает pull/generate).
5. Предоставление неверного ожидаемого SHA — DENIED; попытка объявить `AcceptanceMode Production` — DENIED. Проверки не регистрируют Windows Service, не вызывают `sc create`, `sc start`, не устанавливают ключи/сертификаты и не скачивают веса Qwen.
6. Удаление приложения не удаляет отдельные пользовательские SQLite-данные. Реальный Windows power reboot и живой подписанный HOST на компьютере владельца не испытывались.

### Как выполнить ОГРАНИЧЕННОЕ локальное испытание на ПК владельца

1. Лучше — отдельная тестовая Windows учётная запись или отдельная VM. В любом случае заранее сохранить пользовательские файлы и текущую базу НЕЙРОЗАВОД, если она существует. Текущий артефакт **НЕПОДПИСАННЫЙ**, поэтому не выполнять тест установки защищённой службы и не отключать антивирус/SmartScreen; при сомнении отложить запуск до подписи издателя.
2. Войти в свой приватный GitHub репозиторий и открыть `https://github.com/DSLitvinov1/my_first_repo/actions/runs/40554294409`, скачать из **Artifacts** пакет `Neurofactory-Local-Draft-Windows-Installer-UNRELEASED`. Распаковать в отдельную папку, сначала сверить SHA256 полученного EXE со значением выше. Если не совпадает — не запускать.
3. Если готов к тесту неподписанного локального приложения, выбрать обычную установку **для текущего пользователя без прав администратора**. Установщик содержит ярлык на рабочем столе. Данные размещаются отдельно `%LOCALAPPDATA%\NeurofactoryData`; не запускать другой экземпляр поверх рабочей базы.
4. Открыть ярлык `НЕЙРОЗАВОД — Локальная база`, дождаться браузера по `http://127.0.0.1:8766/`, создать один безопасный тестовый черновик и резервную копию. Настоящая Qwen запускается только если Ollama и модель уже отдельно установлены/доступны локально; автоматически веса не скачиваются.
5. Для независимого просмотра целостности оператор может отдельно выполнить скрипт `acceptance/owner_pc_readonly_acceptance.ps1` из каталога установки, указав каталог установки и **внешний pin SHA256 манифеста** из этого отчёта. Включение `ObserveLocalOllama` делает только read-only HTTP запрос локальному инвентарю Ollama.
6. Если установленной программы нет, программа/файлы повреждены, обнаружен активный процесс `NeurofactoryCoreHost`, или результат не совпадает — никаких автоматически исправляющих действий и эскалации прав. Провести ручной аудит отдельно.

**Нельзя считать локальной физической приёмкой** запись PASS на GitHub-hosted Windows. После получения разрешённого соединения с компьютером владельца через Windows резервный Runner выполнить наблюдение реальных ОС, чистую установку и восстановление, синхронизировать внешний журнал и получить независимый signed REVIEW. Ни один из этих тестов не должен включить рабочие HOST задачи до получения настоящих owner/reviewer/witness полномочий.

### Что всё ещё блокирует production и полную физическую приёмку

- Нет подтверждения online и права запуска на реальном Windows ПК владельца через резервный GitHub Runner. RemoteDesktopCommander в аккаунте имеет 0% оставшихся обращений.
- Нет действительного удостоверенного Authenticode publisher certificate и независимого signed verdict для окончательного EXE и HOST, Issue #11 открыт.
- Установленный local per-user build не поднимает постоянную привилегированную HOST службу. Сквозная Qwen→CORE→restricted SCM→signed receipt→local audit уже PASS в **изолированной GitHub Windows** [№40542374090](https://github.com/DSLitvinov1/my_first_repo/actions/runs/40542374090), **на компьютере владельца не проверено**.
- Без VPS локальный UI/Qwen/черновики возможны, но защищённое производство с требованием independently monotonic external witness нельзя разрешать. Нет реальной подписи ключами владельца и ревизора.
- Запрещены мерж в `main`, auto model download, живые очереди, SKILLS и эффектный HOST до отдельной успешной приёмки.

**Статус на 27.10.2026: установка и локальный read-only acceptance на одноразовой Windows PASS; физическое тестирование и финальный production RELEASE на реальном компьютере НЕ ВЫПОЛНЕНЫ.**
