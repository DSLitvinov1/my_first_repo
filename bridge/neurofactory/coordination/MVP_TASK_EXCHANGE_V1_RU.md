# НЕЙРОЗАВОД — рабочий контракт обмена для безопасного учебного MVP, версия 1

Статус: **изолированный кандидат COORDINATOR**, а не рабочий CORE publisher или утверждённая интеграция. Одна зона изменения — bridge/neurofactory/coordination/ в отдельной ветке PR №12. Исходники CORE/PROVIDERS/OPS/REVIEW/SKILLS/UI не редактируются.

## Реально созданные функции

Первый компонент: mvp_task_exchange.py — чистые преобразования данных и строгие переходы, без внешнего IO, сетевых вызовов, очереди, Ollama и GitHub writer.

1. start: принимает ровно одно предложенное учебное задание: проект, устойчивый task_id, изолированный target, ограниченную цель, точный базовый git SHA, SHA-256 исходника, разрешённую локальную модель, конечный бюджет условных единиц. Результат — PENDING_APPROVAL, ноль платных расходов, никаких разрешений исполнения/повтора/публикации.
2. authorize: для допуска требует соответствующий исходному состоянию внешний approval receipt и реально доверенный callback от защищённого хоста. Любой отсутствующий, неподходящий или просто текстовый APPROVE отвергается. **Внимание:** абстрактный callback не является реализованной криптографической проверкой reviewer — хост и владелец REVIEW обязаны предоставить проверяемое происхождение отдельно.
3. prepare_request: после допуска формирует одно ограниченное сообщение для CORE/PROVIDERS с неизменными task_id, исходным SHA, моделью, резервом попытки. Ничего не отправляет и не меняет HANDOFF.
4. record_provider_result: принимает полный внешний ответ с обязательными task_id, исходным SHA, моделью, локальным происхождением и запретом публикации. Отбрасывает несоответствия. Хранит только контрольную сумму ответа, не сам текст. Статус RESPONSE_UNVERIFIED, не APPROVE.
5. attest_source: только при наличии отдельного доверенного внешнего readback проверяет привязку исходной и новой версий, SHA-256 содержимого и commit проверки. Поддельный или mock-результат не допускается. Статус SOURCE_VERIFIED является *заявлением ограниченного хоста* — без независимого REVIEW это НЕ выпуск.
6. checkpoint + restore: экспортируют последовательность событий и контрольную сумму статуса. Простая SHA-256 — защита от случайной порчи, НЕ аутентифицированная подпись. Для restore обязательно отдельное подтверждение происхождения доверенным хостом; **сам модуль не сохраняет данные долговременно**. Реальное атомарное хранение очереди остаётся исключительной зоной CORE.
7. stop_notice: сохраняемый извне запрет повторной операции при UNKNOWN_MODEL_RESULT, повреждении checkpoint, конфликте lease, отказе REVIEW, неизвестной публикационной квитанции или выходе за область владения. Содержит последнюю проверяемую контрольную точку, всегда BLOCKED / retry=false.
8. project: минимальная read-only проекция задания, версии источника и этапа; никогда не выдаёт publish/run и не заявляет independent APPROVE.

Второй компонент: mvp_task_view.py — отдельный адаптер этапа задачи в карточку для UI/OPS. При отсутствии наблюдения показывает UNKNOWN, всегда запрещает действие, требует соответствие SHA и этапа, не переводит SOURCE_VERIFIED в APPROVED.

## Ограничения, не подлежащие подмене

- Контракт не вызывает и не запускает реальные модели, workflow, Windows-мост, пользователя или GitHub. Это API объектов, а не end-to-end исполнение.
- Предложение для одной задачи пока **не принимается действующим CORE**, в нём проверяются только пакеты 2–8 задач и привязка к старой лабораторной ветке. Это конкретная несовместимость CORE, требующая собственной безопасной доработки владельца.
- Текущий PROVIDERS LocalReply не возвращает task_id и точный входной SHA. Для передачи по новому формату владелец PROVIDERS должен выпускать дополнительную оболочку происхождения результата, не допуская самосогласования.
- OPS reports используют другую схему списка observations и не могут непосредственно принять одну task карточку; требуется read-only адаптер владельца OPS. Никаких claims о live наблюдении.
- SKILLS 12 кандидатов, без реального host-verifier и independent reviewer, не могут предоставлять разрешение на агентное исполнение.
- Старый PR №12 status projector показывает по направлениям только непроверенные источники; наш новый task view — дополнительная схема, не молчаливая замена. Снимок PR №12 указывает на старый coordinator SHA и не является текущим source of truth.
- Все стадии возвращают publication_allowed=false и live_execution_allowed=false; HANDOFF=PAUSED_BY_USER. Другие модули не должны игнорировать эти флаги.
- Никакого фиксированного общего счёта за вызовы модельного API здесь нет. Резервирование символьных единиц не является учётом реальных токенов и расходов.
