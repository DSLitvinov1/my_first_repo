# НЕЙРОЗАВОД — единое распределение параллельных чатов, 13.10.2026

**Статус: согласованный проект распределения.** В GitHub подтверждены параллельные ветки и задания; само наличие открытого чата сейчас не подтверждается GitHub. Другие чаты начнут соблюдать это распределение после передачи им правил. Текущие незавершённые GitHub Actions не останавливать.

## 1. Чаты и ответственность

**«Нейрозавод 1» / «Основное ядро» — владелец CORE.**
Очередь, блокировки двух восстановлений, контрольные точки, восстановление между тремя Windows-мостами, защита от перезаписи чужого состояния. Только новая ветка `neurofactory-core-queue-owned-20261013`, только файлы класса core из `lanes.json`. Не запускать Qwen на новых производственных задачах, не трогать расходы или издателя. Исторические ветки `neurofactory-stage5-pair-recovery-20261013` и `neurofactory-stage5-review-isolated-20261013` — источник патчей, не прямой merge.

**«Восстановление очереди нейрозавода» — владелец HANDOFF.**
Путь Qwen2.5 Coder → независимый Qwen3 → проверка точного исходника → публикация только после одобрения и проверки квитанции. Новая ветка `neurofactory-model-handoff-owned-20261013`. Только файлы stage5_live_*, stage5_isolated_*, stage5_q002_* и модельные адаптеры в своей папке. Не менять общий журнал `stage5_remote_journal.py`, очередь `stage5_development_queue.py` и `stage5_usage_ledger.py`; при необходимости оставлять заявку координатору с тестом.

**«Контроль очереди нейрозавода» — владелец REVIEW.**
Независимая проверка гонок, риска повторов, доверенных квитанций и вердиктов Qwen3. Новая ветка `neurofactory-review-owned-20261013`; только проверяющие модули и отчёты. Не исправлять исполняемое ядро напрямую, а оформлять блокирующее замечание его владельцу. Никогда не считать отсутствие ответа Qwen3 одобрением. Предложение № 2 не объединять без настоящей положительной приёмки.

**«Подключение DeepSeek» — владелец PROVIDERS.**
Только работа с бесплатными провайдерами, пределами Claude Free, Qwen/DeepSeek и fallback-адаптерами в `bridge/neurofactory/providers/`. Ветка `neurofactory-providers-free-20261013`. Ни доступа к платным API, ни изменений общей очереди, ни хранения ключей в GitHub. Не заменять работающего проверяющего моделью, пока не получены сравнимые тесты.

**Этот чат — COORDINATOR.**
Распределение задач, перечень конфликтующих файлов, зафиксированная дорожная карта, единый журнал ресурсов, запрет дублей и объединение только одобренных независимых патчей. Ветка `neurofactory-chat-coordination-20261013`. Сейчас не изменять исполняемое ядро и чужие ветки; доказывать разделение с помощью автоматических проверок.

**«Нейрозавод. Интеллект и навыки» / «Мастер навыков» — отдельная область SKILLS**, если соответствующий чат используется: `DSLitvinov1/lesson3.1`, ветка `neurofactory-skill-master-isolated`. Не работать над очередью, восстановлением и модельным издателем.

## 2. Уже обнаруженные конфликты

- `stage5_remote_journal.py`: правки встречаются в ветках реального цикла и безопасности. Новый единственный владелец — CORE; в другие ветки переносить только отчёты и патчи на рассмотрение.
- `stage5_usage_ledger.py`: одновременно затрагивается ветками реального цикла и безопасности. Владелец — COORDINATOR; проверяющий передаёт замечания без изменения реестра.
- `stage5_development_queue.py`: есть отличия в основной ветке и независимой review-ветке. Владелец — CORE; ветку независимой проверки не сливать целиком.

Запрещено автоматически объединять расходящиеся ветки, если они затрагивают те же файлы. Переносить **отдельные согласованные изменения после сравнения и повторного теста**, а не целый набор коммитов.

## 3. Общие обязательные правила

1. Каждый чат выполняет только задачи своей области и работает только в персональной ветке. Одному файлу — один владелец.
2. Изоляция результатов тестов, временных файлов, журналов и контрольных точек по идентификатору задания и области чата. Не запускать повторно завершённые задания.
3. Проверки на Windows выполнять в отдельном каталоге/группе; не перезагружать машину, не останавливать чужие процессы и не изменять общие secrets.
4. Перед публикацией независимый положительный verdict Qwen3, доказательство идентичности исходников и подтверждённая квитанция GitHub. Неоднозначное восстановление — стоп и аудит, без повтора.
5. Не использовать платные модели, не возобновлять отложенную отправку в ChatGPT, не трогать другие проекты. Пятый этап остаётся открытым.
6. Проверки изменений обязаны проходить `check_lanes.py` и тесты конкретного владельца. Запрет на прямые коммиты в основную ветку «Нейрозавода» из рабочих чатов до независимой приёмки.

## 4. Передача результатов между чатами

Публикуйте краткий отчёт: название чата, ветка, файлы, номер запуска, количество успешных/проваленных тестов, независимый verdict, точный SHA источника, блокирующие проблемы. Запрос чужого файла — через координатора и владельца, не напрямую. Координатор сверяет все результаты и даёт разрешение на минимальное объединение.

## 5. Следующие независимые задачи

CORE: разобрать гонку двух восстанавливающихся процессов и ожидать Qwen3, проверить не-перезапись чужих checkpoint.
HANDOFF: закончить передачу настоящего результата автора второму ИИ, проверить один результат на отдельной ветке без публикации в прод.
REVIEW: получить окончательное заключение Qwen3 по конкуренции и формату квитанций, не ослаблять условия после тайм-аута.
PROVIDERS: только сравнение бесплатных моделей и проверка лимитов без автоматического переключения в производственной очереди.
COORDINATOR: поддерживать реестр путей и проверок, фиксировать новые пересечения, вести расходный журнал без выдуманных сумм.
SKILLS: отдельные навыки с отдельными тестами; активность чата необходимо подтвердить.

**Важно:** эта политика не управляет открытыми чатами ChatGPT автоматически. Довести распределение до соответствующих чатов необходимо отдельно. Ссылка на этот файл в GitHub — общая точка согласования.
