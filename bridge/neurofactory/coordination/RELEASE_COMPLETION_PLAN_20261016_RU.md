## Десять обязательных ворот
Машинное описание `release_readiness_20261016.json` и диагностический проверяющий `release_readiness.py` служат **только** для отображения отсутствующих доказательств. Эти файлы в контролируемом Git-репозитории **не являются** хранилищем секретов, сертификатом владельца или разрешением на работу. Любые утверждения о готовности из этого JSON самозаявленные.

1. **Владелец, проект, источник, политика:** доверенный оператор отдельно подтверждает repo/project allowlist, исходный exact Git SHA, хеш байтов файла и снимка задания, лицензию, ограничение бюджета и криптографически проверенное разрешение владельца.
2. **Подписант:** отдельный защищённый OS principal, ключи только в защищённом хранилище вне доступа DB admin, CORE writer, модели, CI и ChatGPT; ротация/отзыв ключей; публичный ключ закреплён вне неподконтрольной БД.
3. **Контроль отката:** монотонный append-only последний head/sequence с независимой от БД защитой и проверкой после перезапуска; администратор PostgreSQL не может сам переустановить доверенный expected sequence.
4. **Изоляция writer:** реальное разграничение системных субъектов + защищённый sandbox, symlink/reparse, открытая перемещённая родительская папка, запрет изменения вне выбранного project/repo/commit; Windows writer может оставаться выключенным для первого Linux-only релиза, если реально удостоверена Linux-изоляция.
5. **Единственный диспетчер:** свой PostgreSQL с аутентифицированным HTTPS API, per-task epoch/fencing, rate limit, RBAC и аудитом; прямой доступ клиентов к БД запрещён.
6. **Защита эффекта:** конечный файловый/публикующий получатель проверяет текущий epoch, signed scope, idempotency key. Lease CAS без подтверждения конечного эффекта не гарантирует exactly-once. UNKNOWN => STOP и ручная reconciliation, без автоповтора.
7. **Два действительно разных авторизованных клиента:** конкретные физические/изолированные хосты, параллельный claim одной задачи, crash до/после эффекта, offline/API outage, replay/rollback, доказанное отсутствие повторной записи; два соединения одного runner НЕ достаточно.
8. **Рабочая модель:** отдельная проверка бесплатной локальной модели и RAM/CPU/GPU на разрешённой машине; никакого cloud fallback и платного API. До неё допустима лишь детерминированная учебная транзакция без модели.
9. **Внешний REVIEW:** иной реально уполномоченный субъект принимает точно подтверждённые коммиты и логи реального host/keys/CAS/writer + отчёт об атакующих сценариях. Другой чат с тем же GitHub-аккаунтом сам по себе не подтверждает независимость оператора.
10. **HANDOFF:** новое прямое разрешение пользователя только после остальных ворот; текущая пауза не снимается автоматически.
