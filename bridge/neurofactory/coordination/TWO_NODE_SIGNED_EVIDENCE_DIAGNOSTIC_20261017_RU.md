# НЕЙРОЗАВОД — сбор подписанных свидетельств двух узлов (НЕ физическая приёмка)

Дата: 17.10.2026. COORDINATOR Issue #3. Статус: TEST CANDIDATE, LIVE BLOCKED.

Это новый read-only модуль `two_node_witness_diagnostic.py`, предназначенный для следующего шага физической приёмки. Фиксирует операцию и точные 40-значные Git SHA CORE/HOST, одноразовый challenge, task/project, хеш результата, два отдельных цифровых свидетельства с Ed25519 и один победивший/один отклонённый запрос.

Модуль отказывает при отсутствующих/лишних полях, поддельной подписи, чужом ключе, неверной версии исходников, другом проекте, повторе nonce, совпадении двух заявленных устройств/ключей, двух победителях, двух проигравших, неверном числе действий, неподходящих временных метках и ложном `release_approved=true`.

Условие: публичные ключи и заявленные привязки устройств приходят из НЕЗАВИСИМОГО доверенного хранилища оператора, не из подписанных запросов и не из ИИ-чата. Исходный рабочий процесс пока не реализует такое хранилище — CI создаёт только временные Ed25519 ключи внутри ОДНОЙ машины.

**ПРИНЦИПИАЛЬНО:** даже две действительные подписи и разные публичные ключи НЕ доказывают, что это два разных физических компьютера. Поддельные устройства на одной машине могут сформировать тот же набор свидетельств. Поэтому положительная проверка всегда возвращает `hardware_distinctness_independently_proven=false`, `external_operator_authorization_proven=false`, `independent_review_signoff_authenticated=false`, `live_execution_allowed=false`, `release_approved=false`. Документ не разрешает работу моделей, запись в пользовательские проекты, автоматическое объединение PR, HANDOFF или публикацию.

Для настоящей приёмки нужны: два отдельно авторизованных физических компьютера, независимый человек/оператор, вне проекта удостоверенная привязка публичных ключей к устройствам, защищённое хранилище trust-root, серверные журналы CORE/HOST, проверка состояний реального файла до/после, авария fsync→receipt, возврат с резервной копии без второго эффекта, отдельный подписанный вердикт REVIEW. Использовать runbook `TWO_PHYSICAL_NODES_ACCEPTANCE_RUNBOOK_20261017_RU.md` в ветке COORDINATOR. Ни одна процедура на пользовательском Windows ПК этим изменением не запускается.

Не объединять ветку без решения владельца. Переход к живой работе по-прежнему BLOCKED.
