## Что реально создано

Новый исходник `bridge/neurofactory/coordination/advisory_snapshot.py` добавляет чистую функцию `preview_advisory_cards()`. Она читает уже зарегистрированные в `nf_coord_intake_v1` подписанные задания, выдаёт ограниченный отчёт со статусами и описаниями, поддерживает обязательный явный список разрешённых репозиториев (1..50), фильтр проекта и курсорную пагинацию (1..50 записей). События выдаются только из указанной выборки, по убыванию rowid, без возможности записи или запуска очереди.

Структура результата: `schema=neurofactory.coordination.advisory_cards.v1`, `kind=READ_ONLY_UNVERIFIED_UI_DATA`, `cards`, `has_more`, `next_before_rowid`. Каждая карточка содержит только `event_key`, `repository`, `project_id`, `kind`, `mode`, `profile`, `advisory_status`, `description`, `created_at` и явно FALSE для всех флагов полномочий. Нет HMAC-подписи, секретов, токенов, `owner_id`, разрешения на очередь или управляющих команд. Пустая/некорректная область видимости, отрицательные/слишком большие лимиты, поддельный cursor и повреждённый SQLite статус вызывают отказ вместо положительного статуса.

**Важно:** список `allowed_repositories` передаётся вызывающим кодом и сам по себе **не подтверждает право пользователя смотреть проект**. UI-backend обязан получить его из отдельной защищённой сессии/политики и не предоставлять возможность задавать произвольный список клиентом. Нельзя выставлять endpoint в Интернет, считать статус `ADVISORY_READY_NO_EXECUTION` подтверждением владельца или превращать поля карточки в право выполнить задачу.

Функция намеренно не изменяет исходные таблицы и не использует HTTP, токены, реальные модели, HOST, CORE, файловый writer или publishing. Существующий UI пока не интегрирован; владелец UI должен выполнить безопасное подключение в собственной области и получить отдельный аудит.
