# CORE → TRUSTED HOST: новая учебная транзакция с единственным конечным файловым эффектом

Дата: 17 октября 2026. Статус: **изолированная интеграция Linux/PG16, не рабочая очередь**.

Новая CORE-owned `bridge/neurofactory/development/core_owned/offline_receiver_client.py` (Git blob `fffe9c513f3acc6e5d11e7baa26917648d6f9a4f`) — test-only клиент, который проверяет подлинное локальное состояние `OneTaskCore`, один заданный исполнитель/исходный Git commit/target/содержимое/токен, затем **не пишет сам ни одного файла**, а вызывает конечный HOST receiver. Не восстанавливает отключённый `OneTaskCore.apply_offline_test`, не использует локальный положительный тестовый callback как производственные полномочия. Вся реальная учебная запись происходит внутри изолированной `OfflineFencedFileReceiver` от HOST, которая самостоятельно перепроверяет подписанный scope, Postgres CAS текущей аренды и DB intent, заранее фиксирует UNKNOWN, открывает файл через dirfd/O_NOFOLLOW/O_EXCL, fsync и ставит test receipt. Успех означает `CORE_TO_HOST_ONE_EFFECT_OBSERVED_OFFLINE_ONLY`, все flags production/merge/retry/pub FALSE.

Новые тесты `test_offline_receiver_client.py` (blob `57453cf4a6e7f0f950d0fcf3f299702fc5676abe`) и scoped CORE workflow `.github/workflows/neurofactory-core-owned-pinned-receiver.yml` pin точно HOST исходник `0c33d8181e102e2ca3f47559ae6abeb2f4b72757` в read-only second checkout.

**Реально проверено:** GitHub-hosted Ubuntu24.04, ephemeral PostgreSQL16, real temporary Git repository with commit, real CORE SQLite checkpoint + real signed HOST transaction, exact CORE candidate `bb5ec473ff62e29ba75b69b88bedbde3f7d02b4a`, [Actions №39025759130](https://github.com/DSLitvinov1/my_first_repo/actions/runs/39025759130), job 117376302089 — **9/9 PASS**: ровно один действительный учебный файл записан HOST; bytes SHA совпали; отсутствует файл в CORE sandbox; повторный effect denied; чужой worker, forged signature, чужой target, PG lease expired, HOST unavailable denied; UNKNOWN after fsync prior to receipt STOP/no duplicate; CORE old direct write remains denied. Маркеры реального журнала `CORE_TO_HOST_REAL_TEMP_FILE=ONE_WRITE_ONLY`, `CORE_TO_HOST_UNKNOWN=STOP_NO_DUPLICATE`.

**Production RELEASE пока заблокирован:** оба этапа запускаются только при явных `NF_CORE_OFFLINE_RECEIVER_TEST_ONLY` + `NF_HOST_RECEIVER_FIXTURE_ONLY` в ephemeral Linux; подписант ephemeral и допускается самими тестами; реальная система owner/repo ACL, operator/key custody, DB owner resistant highwater, authenticated HTTPS CAS, отдельная OS identity и OS-protected final recipient ещё не развёрнута. Подписанная область из теста не может служить production user approval; реальная ОС и два разных физических компьютера не испытаны. Нет независимого human/security operator signoff. Никакие реальные модели, платы API, публикация, HANDOFF, merges не запускались.
