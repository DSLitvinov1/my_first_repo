## Что реально реализовано

Новый отдельный исполнительный кандидат `bridge/neurofactory/trusted_host/offline_operator_anchor.py` (physical Git blob `a762cf1854d0d8191db8891e2d8236c699d248d5`). В режиме `NF_OPERATOR_ANCHOR_FIXTURE_ONLY=1` на Linux программа отказывается работать от root, требует собственную приватную директорию `0700` и проверяет uid/mode/key/anchor. Создаёт временный Ed25519 private key `0600` непосредственно в каталоге подписанта, не печатает его и не записывает в репозиторий. Отдельная принадлежащая этому uid контрольная точка хранит последовательный номер и SHA256 цепочки; каждый шаг подписывается Ed25519. Случайный запрос может только расширять тестовую цепочку, а **не выдаёт право записи файла**. Верификатор требует заранее независимо закреплённый public key fingerprint, проверяет подпись и строго равное текущему защищённому номеру/head, отказывает старой даже подлинно подписанной квитанции. На стороне подписанта используется Linux file lock, atomic replace и fsync для последовательного обновления; старые digest запрещены. Любые возвращаемые флаги `execution_allowed` и `production_owner_authenticated` всегда FALSE.

Это полезная тестовая реализация независимого от рабочей PostgreSQL логического highwater, **НЕ** защищённая production identity: любой процесс с UID подписанта или root, либо злоумышленник, способный заменить исходно доверенный публичный ключ, может атаковать основание доверия. Генерация пары в тесте не доказывает легитимность владельца проекта, issuer authorization, TLS или identity конечного writer.

Отдельно исправлено совпадение имени тестового файла `operator.py` с модулем Python `operator` и проверка закрытых метаданных от имени подписанта вместо неуполномоченного runner UID.

Программа signer владеет ключом и head с 0600/0700; DB actor не может прочитать ключ, открыть/переписать tip и повторно выполнить bootstrap. DB actor восстановил в настоящем PostgreSQL 16 старый корректно подписанный snapshot, но signer-owned latest tip обнаружил rollback и отказал в признании старого snapshot текущим. Неавторизованный UID отклоняется даже при доступе в общую группу. Реальная подпись и pin сопоставляются с защищённым текущим signer tip.
