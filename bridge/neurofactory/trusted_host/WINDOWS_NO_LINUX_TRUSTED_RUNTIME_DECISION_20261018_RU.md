# Решение: «НЕЙРОЗАВОД» без отдельного Linux-сервера

Дата: 18.10.2026. Статус: **выбран Windows-путь разработки, не разрешение на производственную запись**. Основной репозиторий: `DSLitvinov1/my_first_repo`. Отдельная ветка кандидата `neurofactory-windows-local-trusted-runtime-20261018`; основной HOST/CORE/REVIEW не менялись и не объединялись.

## Решение владельца

Отдельный Linux HOST — не обязательная инфраструктура. Развивать **локальный Windows Trusted Runtime** на уже имеющемся авторизованном Windows-компьютере и использовать существующий Windows self-hosted GitHub Runner исключительно как рабочий исполнитель с ограниченными правами.

**Не упразднять саму границу доверия:** ИИ, локальные модели, Codex, GitHub Runner и CORE не получают права напрямую писать в защищённые проекты. Только отдельная защищённая Windows-служба-получатель под независимой системной учётной записью принимает ограниченные операции по подписанному разрешению. Ни назначение через Issue, ни локальный токен, ни ответ ИИ, ни одобрение от того же процесса не являются достаточной авторизацией.

## Реализуемый вариант А: один Windows-компьютер — локальный MVP

1. **Windows исполнитель**: текущая разработка и локальные Qwen/другие бесплатные модели продолжают работать через GitHub Runner/очередь CORE под обычным, непривилегированным Windows-пользователем. Исполнитель не обладает правом менять службу-получатель, её каталоги, ключи, ACL, системные файлы или локальные настройки безопасности.
2. **Защищённый получатель**: отдельно установленная и обслуживаемая владельцем Windows Service, отдельный Service SID или выделенная сервисная учётная запись, защищённая папка и объект IPC. Локальный вход через Windows Named Pipe с **явно заданной DACL для конкретного SID**, запрет NETWORK/Everyone/Anonymous, проверка SID клиента и подписи с точными task/repo/project/source SHA/epoch/fence/idempotency/content/target. Никогда не оставлять ACL pipe по умолчанию. После получения сообщения проверять текущую аренду, fsync и защищённую квитанцию. Запуск только после отдельного разрешения владельца.
3. **Ключи**: закрытые ключи не должны лежать в репозитории, ChatGPT, Runner secrets или произвольных файлах рабочего пользователя. Microsoft Windows CNG/TPM Platform Crypto Provider или другой системно защищённый ключевой провайдер — при доступности и внешнем подтверждении оператора. **Нельзя считать Ed25519-подпись и TPM CNG ECDSA P-256 взаимозаменяемыми.** Для аппаратно защищённой Windows-подписи нужен отдельный версионированный криптографический контракт и проверяемый переход; прежние Ed25519 тесты не меняются молча. Подписанное разрешение владельца, выданное на другом устройстве, допускается только после независимой проверки его публичного ключа и актуальных прав.
4. **База и журнал**: можно хранить PostgreSQL локально на том же Windows-компьютере с отдельными DB-ролями, минимальными правами и бэкапом. Однако PostgreSQL, SQLite и другой журнал под тем же администратором НЕ доказательство необратимого anti-rollback: возврат всего диска/виртуальной машины к старому состоянию способен вернуть старые значения. Для строгой защиты от повтора при откате нужен **независимый внешний highwater/witness** (другой отдельно администрируемый доверенный сервис или отдельное физическое устройство), который принимает подписанный claim, сохраняет одноразовый резерв до эффекта и запрещает второй.
5. **Защита файла**: заранее заданный каталог тестовой зоны; запрет junction/reparse-point, обхода путей, подмены имени, перезаписи, дубликатов, абсолютного и относительного выхода за корень, контроль fsync и журнал UNKNOWN до записи. Любая неопределённость после записи — остановка и ручная сверка, без автоматического повтора.
6. **Режим локального MVP**: один физический компьютер достаточен для развития интерфейса, моделей, создания заданий, генерации файлов **строго в учебном изолированном каталоге** и ручного подтверждения. Полная автономная запись во внешние реальные проекты запрещена до независимой защиты от отката и REVIEW.

## Вариант Б: промышленная Windows-система БЕЗ Linux

Если требуются реальные автоматические изменения проектов и защита от администратора локального компьютера, оставить Windows CORE и Windows Receiver, но подключить внешний **подписывающий/неоткатываемый свидетель** в другом доверенном домене (другой Windows-компьютер, внешний сервис с независимыми ключами и отдельными полномочиями). Linux при этом нигде не обязателен. Канал — взаимная аутентификация с закреплёнными сертификатами или эквивалент, одноразовое резервирование и независимый журнал до файлового эффекта. Независимый REVIEW принимает на точных SHA и двух независимых доменах риска.

Если внешнего свидетеля нет, нельзя оставлять прежнюю гарантию «защита от полной компрометации компьютера и отката диска»: её нужно **снизить до локального контролируемого пилота**, а не тихо считать выполненной. Допускается ручное подтверждение владельца перед необратимой операцией, но при полном откате компьютера автоматическая защита от повторного эффекта не гарантируется.

## Практические задачи Windows-пути

| Часть | Что сделать |
|---|---|
| TRUSTED HOST Windows | Спроектировать защищённую Windows Service и отдельный Service SID / учётную запись, строгий Named Pipe ACL и аутентификацию клиента; **не использовать Linux fixture writer** |
| CORE | Добавить Windows-адаптер доставки; сохранить подписанные разрешения и запрет локального прямого writer |
| PostgreSQL | Перенести операторски одобренную структуру постоянной базы; не импортировать тестовые логины или `nf_test` |
| Криптография | Зафиксировать алгоритм подписи, отдельные публичные ключи и защищённое хранение; выполнить межплатформенную проверку Ed25519 либо версионировать CNG ECDSA P-256 |
| Отказоустойчивость | Crash/restart, snapshot rollback, повторная доставка, неизвестный результат, TTL/lease/fencing/reparse-point |
| UI/OPS | Показать «локальный пилот / защищённый допуск заблокирован», состояние исполнителей и ресурсы CPU/RAM/VRAM |
| REVIEW | Проверка Windows угроз, прав службы, хранения ключей, реальных сценариев отказа, точных коммитов независимым ревизором |

## Критерии локальной приёмки (не выпуск в производство)

- Назначение задания, выполнение Qwen, сохранение **одного** инертного файла в изолированном каталоге и отображение результата в UI.
- Пять отрицательных испытаний: поддельное разрешение; неправильный SID/чужой канал; истёкшая аренда; повторная операция/откат SQL; junction/reparse/path traversal, плюс авария после записи.
- Реальный перезапуск Windows-службы и компьютера после разрешения владельца; проверка истории. При отсутствии независимого witness не утверждать защиту от отката всего диска.
- Независимый reviewer подтверждает конкретный режим. Пилот не является самостоятельным production approval.

## Текущее состояние

Подтверждён один подключённый Windows-компьютер `WIN-LIDC05TBOQD`, но удалённое выполнение команд через Desktop Commander ограничено месячной квотой. Не повторять попытки и не обходить квоту. **Никакой установки/изменения системных прав на компьютере не выполнено.** Linux HOST больше не является обязательным *для Windows-пути проекта*, но подписанное доверие, минимальные права, внешняя защита от отката (для автономного продакшена) и отдельный REVIEW остаются обязательными.

**Никаких слияний PR, активации HANDOFF, платных API и рабочей очереди без разрешения владельца.**
