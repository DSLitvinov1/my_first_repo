Дата 17.10.2026. TRUSTED HOST Issue #14 / draft PR #15. Вся реализация только в ephemeral GitHub-hosted Ubuntu24.04 / PostgreSQL16 `nf_test`, не на компьютере пользователя. Ни одного production пути не разблокировано.

Новое:
* `offline_os_separated_effect_receiver.py`, точный Git blob `030a4c12111417af23e5dfa3fe4d61daf110312f`, получает подписанные разрешения через group-restricted Unix socket как пользователь **nf_effect**. Отдельная подписывающая сторона **nf_signer** хранит private Ed25519 key/monotonic tip и собственную test-only signer-owned политику владельца и Git source; исполнитель/DB actor — **nf_db_actor**. Все три UID действительно раздельны **на одной физической временной машине**.
* nf_effect, не клиент, владеет файловым каталогом 0700, закрытой конфигурацией 0700/0600, ранее утверждённой точной публичной идентичностью подписанта и издателя разрешения, адресом подписанта и UID разрешённого клиента. Клиент только отправляет подписанный packet, подписанный witness и байты, но **не может выбрать доверенный ключ, конечный root, системный UID или режим проверки**.
* Сервер проверяет системного вызывающего через Linux `SO_PEERCRED`. Затем отдельным UDS проверяет signer-owned точное разрешение и свежий независимый монотонный маркер через проверенную client/server `SO_PEERCRED`. Закрытый ключ клиенту не выдаётся. Защищённый receiver сам заново проверяет живую PostgreSQL-аренду, fencing/epoch/task/worker/target/content и уникальный журнал операции UNKNOWN до создания файла O_EXCL/O_NOFOLLOW + fsync. При неподтверждённом результате ответ **DENIED_OR_UNKNOWN_MANUAL_STOP** (никакого автоматического повторного необратимого действия).
* Базовый offline receiver остаётся импортируемым тестовым модулем, но `nf_db_actor` **не владеет и не может даже открыть** receiver-owned директорию. Следовательно, прямой тестовый API не позволяет этому OS principal обойти на практике ограничение по файлам внутри защищённого каталога. Пользователь с root/nf_effect всё ещё входит в trusted computing base; это НЕ аппаратно удостоверенный производственный сервер.
