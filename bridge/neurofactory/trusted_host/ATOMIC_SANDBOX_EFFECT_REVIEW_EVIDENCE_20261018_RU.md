## Реализация

Создан отдельный ограниченный учебный исполняемый модуль `sandbox_atomic_effect_candidate.py`, Git blob `c067e86ce03f5999f59c187d2bece325d9ba3cbc` и адресный `test_sandbox_atomic_effect_candidate.py`, Git blob `4442f28688341007db8a4c5aad0a48becca94630`. Тестовый Linux workflow `.github/workflows/neurofactory-trusted-host-owned-atomic-sandbox.yml`, Git blob `412e5480d08f2b143f45b3d22dfafe9da70691af`.

Условия фактического одноразового эффекта ВРЕМЕННОЙ СРЕДЫ:
- Жёсткие `NF_DB_SCHEMA_CI_ONLY=1` и `NF_ATOMIC_TEST_ONLY=1`, только disposable PostgreSQL16, приватная папка `/tmp/nf-atomic-ci-*` правами 0700. Ни исходники проектов, ни домашние каталоги, ни рабочие сервисы не изменяются.
- Сначала реальная PostgreSQL транзакция с `FOR UPDATE NOWAIT` аренды и единственного `UNKNOWN` receipt. Внутри НЕЗАВЕРШЁННОЙ внешней транзакции вызывается существующий проверяющий `inspect_current_lease_and_receipt` с четырьмя подписанными ролями и операторскими pinned roots. Поэтому блокировка остаётся удержанной через последующие операции; отличие от самостоятельного read-only preflight PR #18.
- Далее на учебном интерфейсе witness выполняется единожды внешняя логическая резервация `UNKNOWN` с привязкой к подписанному scope, operation, sequence и journal root. Начиная ДО вызова witness любой таймаут, потеря подтверждения, поддельный ack или отказ должен приводить к `SandboxEffectUnknown` и запрету автоматического повтора.
- После подтверждения в приватной Linux директории создаётся файл с `O_EXCL | O_NOFOLLOW`, правами 0600, выполняется `fsync` файла и родительской директории. В той же удерживаемой PostgreSQL-транзакции обновляются receipt `UNKNOWN→COMPLETED` и lease `CLAIMED→COMPLETED` с повторной проверкой epoch, fencing и deadline. При неясном результате COMMIT файл не удаляется, а операция помечается UNKNOWN.
- Результат модуля всегда включает `live_execution_allowed=false`, `release_approved=false`, `automatic_retry_allowed=false`, `real_external_witness_attested=false`.

## СУЩЕСТВЕННЫЕ ОГРАНИЧЕНИЯ: ПРОИЗВОДСТВО НЕ ГОТОВО

**witness в новых тестах — отдельный объект тестового процесса, не независимый физический или сетевой доверенный сервис, не TPM/HSM, не доказательство неперезаписываемого внешнего highwater.** Тест отката восстанавливает локальную SQL-таблицу и удаляет локальный файл при сохранённом in-memory witness; это учебная имитация угрозы, а не настоящий OS reboot, питание или восстановление из резервной копии физического компьютера. Настоящая проверка владельческих полномочий GitHub, независимый operator enrollment, защищённый listener и независимый REVIEW отсутствуют.

Нынешний CORE `offline_os_receiver_client.py` (test-only) требует формат signer permit + owner grant и не является совместимым прямым клиентом новой четырёхролевой scope-программы. Поэтому заявлять завершение реального пути CORE→HOST→offhost witness пока нельзя: владелец CORE должен предоставить собственный авторизованный клиент новой версии, HOST владелец — отделённый процесс и внешний журнал, независимый REVIEW — подписанный вердикт. Эти направления НЕ изменены данной веткой.

Отдельный новый PR — DRAFT для адресной независимой технической проверки, НЕ merge. Не исполнять на пользовательском ПК, не использовать в производственных средах. RELEASE BLOCKED, HANDOFF PAUSED_BY_USER, очередь OFF, платные API не подключать.

## Задания владельцам CORE / HOST / REVIEW

1. HOST: согласовать прозрачный неизменяемый wire contract четырёх подписей, реального актуального lease/fencing, сетевого offhost reserve/ack, O_EXCL+fsync и UNKNOWN. Убрать обход test-only API из доступного реальным процессам маршрута, не отключая текущие тесты. Перед настоящей установкой подтвердить оператора/ключи/права и внешнее устойчивое highwater.
2. CORE: только в собственной области разработать совместимый test/proposal adapter к HOST-ограничениям, запретив локальную запись, повтор после UNKNOWN, несовпадение исходного коммита/owner/worker/lease. Не использовать SQL preflight как permission.
3. REVIEW: на точных HEAD оценить гонку между witness reserve, SQL lock, файловым fsync и receipt, два независимых устройства, отказ witness после резерва, крах до/после COMMIT, совмещённый rollback и старые прямые fixture APIs. Заключение APPROVE/REJECT/INCONCLUSIVE отдельно от автора; production выпуск до физической проверки и полномочий запрещён.
