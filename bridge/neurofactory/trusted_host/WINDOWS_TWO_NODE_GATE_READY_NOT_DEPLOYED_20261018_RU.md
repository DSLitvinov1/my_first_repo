## Как будет проводиться РЕАЛЬНАЯ установка — только после разрешений

До изменения Windows A/B независимо уполномоченный владелец в закрытом операторском реестре должен зафиксировать:
1. Устройства A/B, их физическую раздельность, удостоверенные аппаратные идентификаторы, отдельные права/администраторов и согласованный срок испытания; право оператора остановить испытание.
2. Только публичные pinned keys оператора, получателя A, свидетеля B и независимого REVIEW; закрытые ключи и секреты **не** отправлять в чат/GitHub/CI, предпочтительна невыгружаемая аппаратная custody. Самоподписанные фикстурные ключи и сертификаты НЕ допускаются как рабочие.
3. Проверенную защищённую Windows службу получателя (отдельный Service SID/права и ACL файла/Named Pipe), защищённый свидетель B на независимо администрируемом устройстве, защищённый канал mTLS с закреплёнными сертификатами и внесетевой mono/WORM highwater, который не может откатить администратор A.
4. Письменное разрешение на ограниченную тестовую установку и **конкретные** перезагрузки A/B; независимый REVIEW предварительно проверяет план угроз. До этого никаких OS state changes.

После одобрения сначала собирают исходные evidence на устройствах A/B, фиксируют подлинные boot IDs, время загрузки и защищённый witness highwater. Затем **на настоящем оборудовании** выполняют по отдельным согласованным операциям: (1) forged owner DENIED; (2) чужой TLS/SID DENIED; (3) просроченный fence DENIED; (4) LOST_ACK UNKNOWN_NO_RETRY с сохранившимся независимым reserve; (5) один инертный SUCCESS с проверенным hash и receipt; (6) восстановление ранее сохранённой БД/файла A и повтор DB_ROLLBACK_REPLAY DENIED B. Между измерениями делаются разрешённые реальные рестарты обеих ОС с независимым доказательством, что свидетель B не откатывался вместе с A. Каждый сценарий должен иметь отдельные подписи A и B и отличающиеся идентификаторы двух отдельных устройств. Не отправлять секреты в логи.

По завершении независимый назначенный ревизор САМ повторно проверяет exact Git SHA, журналы, доверенные ключи, boot evidence, физический домен и подпись, затем выносит отдельный подписанный вердикт на точные SHA. Авторский тест/самодельная подпись **не** заменяют этот вердикт.
