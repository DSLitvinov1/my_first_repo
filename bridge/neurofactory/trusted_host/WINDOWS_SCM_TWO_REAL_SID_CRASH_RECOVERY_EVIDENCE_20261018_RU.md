## Что фактически работает

1. Тестовый администратор в одной временной Windows-машине зарегистрировал через **настоящий Windows Service Control Manager** службу `NeurofactorySandboxReceiverCI` как `NT AUTHORITY\LocalService`. Скрипт проверил не только Service StartName, но и идентичность реального запущенного процесса через Windows WMI.
2. Отдельно создан неадминистративный Windows-пользователь со своим настоящим SID; клиент запускался под его security token через `CreateProcessWithLogonW` с чистым окружением. SID проверен им самим и сервером посредством `ImpersonateNamedPipeClient`. Worker не получает приватный ключ владельца, не может читать каталог службы и не может создать в нём собственный файл.
3. Получатель открывает настоящий Windows Named Pipe с явным DACL только для разрешённого SID. Windows-служба проверяет SID ПОСЛЕ bounded ReadFile, но ДО обработки подписанного задания и filesystem effect.
4. Тестовый оператор отдельно подписывает ограниченное одним файлом Ed25519 разрешение, привязанное к настоящему CORE task/project/Git source SHA/op/target/content. Тестовый CORE действительно создаёт, сохраняет и выдаёт одну аренду `CLAIMED` в собственной SQLite; код CORE берётся из точно закреплённой версии, не подменяется копией/моком. Единственная целевая запись производится получателем в собственной закрытой папке и имеет строго фиксированное имя `windows_pilot.txt`.
5. До файла создаётся `UNKNOWN_NO_AUTO_RETRY` метка с исключительным созданием и fsync; файл пишется только `CREATE_NEW`, без замены существующего. После любого неопределённого исхода получатель запрещает повтор и требует ручную сверку.
6. Администратор CI в конце удаляет созданную тестовую службу и тестового локального пользователя. Все изолированные машины GitHub уничтожаются; настоящий ПК владельца не изменялся.

## Что НЕ утверждаем

**НЕ промышленная готовность.** Несмотря на настоящее разделение двух Windows SID, код намеренно ограничен одноразовым безопасным файлом и временной SCM-службой теста. На настоящем ПК не зарегистрирована служба, не закреплены приватные ключи Windows CNG/TPM и не настроена защищённая постоянная база.

Ключ проверки подписи Ed25519 в CI временный; настоящий отдельно уполномоченный владелец не подтверждён. Сама служба не перепроверяет lease в защищённой PostgreSQL непосредственно перед эффектом, а доверяет ранее подписанному учебному scope от тестового оператора. Отдельного off-host monotonic antirollback свидетеля/внешней аппаратной гарантии нет. Запуск после полного отката Windows-диска не проверен, равно как реальная перезагрузка Windows. Успешная аварийная остановка процесса **не эквивалентна power-loss durability или reboot**. Независимый REVIEW на точных версиях не получен.

GH runner создаёт временные локальные учётные записи с паролем только в памяти одноразовой CI машины; настоящий оператор и пользовательские ключи в GitHub/чат не передавались. Важная граница: GitHub CI администратор имеет более высокие права, чем LocalService и worker, поэтому испытание показывает изоляцию **между службой и обычным исполнителем, но не защиту от компрометации администратора ОС**.
