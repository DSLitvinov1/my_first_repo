## Строгие входные условия отдельной двухмашинной приёмки

1. Владелец подтверждает точное целевое устройство HOST, отдельное устройство witness, пределы испытания, право установить службы/сертификаты и **конкретно** разрешает reboot HOST и восстановление только тестовой базы. Witness при этом остаётся работающим на действительно другой машине. Подтверждение должно быть явным и не подразумевается выполненным по этой задаче.
2. Независимый оператор лично или по защищённой аппаратной аттестации сверяет каждый физический узел, stable hardware identity и TLS public fingerprint, заверяет данные своим отдельно закреплённым криптографическим ключом и фиксирует ограничения доверия. Нельзя считать два разных процесса, контейнера или GitHub runners двумя удостоверенными машинами пользователя.
3. Владелец реально доказывает владение своим **постоянным** закрытым ключом на отдельно согласованном устройстве. Оператор независимо проверяет через официальный GitHub API numeric user/repo ID, актуальную роль/полномочия и утверждённую область, подписывает снимок прав и удостоверяет owner nonce. Закрытые ключи/токены остаются вне чата и GitHub.
4. Отдельный защищённый Linux свидетель на машине Б имеет private signer key, отдельное durable write-once хранилище, авторизованный закрытый listener, защиту от rollback (при требовании стойкости к одновременному откату двух машин необходим третий аппаратный/внешний корень доверия). HOST на машине А не контролирует это хранилище.
5. Затем только после отдельного разрешения проводится одна учебная операция: на машине Б выполняется fsync неизменяемого UNKNOWN маркера, signed ACK по mutual TLS; на машине А — 1 реальный файл с точным SHA; после reboot машины А восстанавливается старый local PostgreSQL/recipient backup и проверяется запрет повторного эффекта при неизменённом Б, а также случай разрыва связи/потери ACK и конкурентных запросов. Не повторять опасную запись автоматически.
6. Независимый назначенный REVIEW (не разработчик, не тот же оператор, который внедрил систему) подписывает свой вердикт на точных HEAD SHA, идентификаторах обоих устройств, разрешённом тестовом проекте, независимых логах, сроке полномочий, факте рестарта и восстановления. Отсутствие такого verdict означает `REJECT LIVE`.
